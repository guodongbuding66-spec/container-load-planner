## 本轮功能

在整托查看／托内编辑中增加“层型模板与批量叠层”。用户将当前物理层保存为带名称、版本的模板；若套装跨层，连同完整组件保存为一个层型块。每模板最多 500 箱、200 个产品引用，最多保存 20 模板。仅支持长方体箱规。

应用时选择当前托盘内 XYZ、四向水平旋转、重复次数（1–20），可相邻层型交替 180°。模板只描述原始箱规和相对排布，重量、颜色、允许朝向及承重使用当前订单。优先匹配原订单行；跨订单只有 SKU 唯一、尺寸与套装比例一致时允许匹配。同名多行不自动合并，箱规变化要求重新保存。

全部重复层作为一次完整方案事务：任一层越界、碰撞、悬空、超重、超限高、违反木箱净空、拆套或超过订单余量，整次失败。锁定其他整托及箱体保持不动；编辑草稿可撤销／重做，点击“采用托内调整”后再同步三维、重量、清单及导出。交替旋转本身不证明堆叠稳定。

模板库独立于箱位草稿，保存模板不修改订单、库存或双算法结果，也不触发自动重算；本机刷新和工作区备份保留模板。应用后的实际箱位通过既有备份、CSV、报告和 PDF 路径交付。放弃箱位调整不会删除模板；刷新未备份的手动箱位仍遵循原方案保存规则。

## 两站实际软件验收

已在 [Cloudflare Pages](https://container-load-planner.pages.dev/) 和 [Vercel](https://container-load-planner-gray.vercel.app/) 的正式地址确认算法版本 0.39.0。主界面不再有逐托进叉、设备单段和连贯搬运入口；底座实测、静载／动载／货架载荷资料仍可编辑。两站应用控制台无错误。

| 操作 | 实际结果 |
| --- | --- |
| Pages：400 × 300 × 200 mm、10 kg 的长方体，800 × 600 × 100 mm／25 kg 托盘，货物限高 600 mm | 保存四箱物理层为 `QA-4-carton-layer`，版本 `qa39`，占用 800 × 600 × 200 mm |
| 清空托内草稿，三次重复并交替转 180° | 一次加入 12 箱；总高 700 mm，整托 145 kg；中层旋转轴符号为 `[-1,-1,1]` |
| 再次在原点应用；空托应用四次或七次 | 分别因重叠、限高、超过 24 箱订单量而拒绝；失败前后的箱数及编辑版本不变 |
| 撤销／重做 | 三次叠层作为一次历史事务，12 箱与空托之间一步切换；空托保留 25 kg 自重 |
| 重复次数留空 | 验证应用和采用按钮均禁用；恢复数值后恢复操作 |
| 采用、导出、刷新、再计算 | 采用后同步整托及整柜清单；刷新仍保留一份四箱模板；未备份手动箱位不承诺自动保留 |
| 实际下载的工作区备份 | 使用当前 `parseWorkspaceBackup`／`restoreWorkspacePlans` 重新校验通过；12 个唯一箱体 ID、XYZ、尺寸、方向及轴符号与原快照相同，总重 145 kg |
| 实际下载的 CSV | 12 条货物记录加 1 条托盘记录，合计 145 kg |
| 中英文与 Vercel 模板保存 | 英文模板控件和资料说明可用；Vercel 以默认 BED-205 层型完成保存与删除 |
| 验收后清理 | 两站删除临时 QA 模板并恢复默认直接装箱；双算法各 116 箱，总重 3,842 kg |

证据为无业务数据的 QA 样例：[层型应用画面](field-upgrades/evidence/v0.39.0-layer-templates.jpg)、[工作区 JSON](field-upgrades/evidence/v0.39.0-workspace.json)、[坐标 CSV](field-upgrades/evidence/v0.39.0-coordinates.csv)。旧叉具原始字段因兼容旧备份仍可出现在导出中，不代表具体设备操作已核验。

当前 Chrome 未启用 WebGL，上述是实际坐标回退视图与完整数据／交互验收；真实 GPU、真实浏览器图形组合和现场实装验证仍为 PENDING。默认示例的 116 箱不等于所有现场校核通过，原有门洞路径、承重和加固状态按当前资料显示。相邻层旋转只改变排布，未验证抗倒或材料强度。
