## 本轮完成

在“只打托／先打托后装柜”的各包装规格中增加可选底座实测尺寸：面板、底板与横担厚，单板宽和支承块长宽。保留规则等距排布，部件位置由当前尺寸和根数确定；不是任意结构建模器。通用旧文件保持原有比例几何。实测尺寸越界、部件相互覆盖或没有有效叉孔高度时明确阻止采用该配置。木箱四角传力路径使用同一实际部件，结构改变使旧核对标记失效，脚与立柱不一致时仍不通过。

自动列出长、宽方向的全深度贯通矩形净孔，不把面板之间向上敞开的缝隙当叉孔，也不将孔洞用于塞货。两根矩形叉具的宽厚长、中心间距、横向中心、底部高度、插深、叉尖余量、检查间隙和完全抽出后的额外净距分别输入。宽厚长、间距或插深为 0 时保持未核验，不代入默认设备。

先检查本托实际部件与双叉包络，再按原始 LWH／WLH 朝向转换到装柜坐标，检查完整抽叉直线扫掠与当前静止货物、其他整托保留包络、柜内区域及柜壁。闭式车辆只在后门净空内允许包络伸出柜外；只打托的编组坐标不作为现场边界，开放装载超出模型时保持未核验。结果列出受阻部件／货物 ID 和扫掠坐标；局部图与装柜坐标明确区分。

来源、版本与人工核对绑定几何、叉具和载荷资料；更改参数后须重新核对。颜色与透明度不影响核对。静载、动载、货架载荷及来源分别记录，未填写不推算；没有复制现有求解载重上限，也没有接入自动搬运或货架放行。

## 保存与交付

各规格、模板、工作区和两个策略的完整结果保留同源字段。CSV 增加叉具接口 JSON 和独立预检范围，包装结构 JSON 保留实测尺寸；与区域记录、包装候选和尺寸双方案组合时仍保持行列对齐、尺寸方案两列位于最后。客户与离线报告、PDF 为局部资料摘要；PDF 长来源会截短，完整资料保留于工作区及 JSON。

逐托预检 JSON 在导出时重算，记录方案 ID、创建时间、核查时间、引擎／几何版本、整托姿态、配置和阻挡。它不能当成工作区或采用方案导入。预检不会修改订单、数量、坐标、包装自重或五项方案复核状态；通过仅限所输入矩形包络的几何关系。

## 验证记录

新增 30 项测试，覆盖旧模型兼容、实测边界、墩式四向／纵梁方向差异／实心无孔、叉具超限、完整抽叉、旋转、邻箱／邻托／区域／壁面／后门、开放边界、缺资料、核对失效、三类载荷分离、多规格与双策略恢复、篡改拒绝、报告转义、PDF 文本边界、中英文、无效草稿和无采用入口。最终 `npm run build:pages` 通过：864 项单元测试（73 个文件）、21 项 HTML 检查、TypeScript、lint 零错误（3 项既有警告）与 Next 静态生产构建。正式站发布与实际操作验收在交付前核对。

## 尚未覆盖

不求叉车本体、转弯半径、起升／倾斜／落位动作、货叉弯曲几何、底轮／门槛、动态能力或载荷中心曲线。当前最终位置的静态抽叉受阻，不等于证明不存在另一作业顺序。非等距支承位置、挖槽纵梁、任意异形叉孔与实际损伤另行扩展。三类载荷为资料记录，不是本轮强度判定。真实 GPU、多浏览器与代表订单现场试装仍为 PENDING；木箱仍按原有规则底置。
