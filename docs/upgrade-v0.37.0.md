# v0.37.0 设备直线搬运动作预检

日期：2026 年 10 月 17 日。基线 v0.36.0，GitHub `9bca28a7f34017e36a4320afe918bebd7a84d26e`。范围见[阶段 010](field-upgrades/010-equipment-actions.md)，后续仍按[未完成台账](field-upgrades/unfinished-roadmap.md)实施。

## 本轮范围

整托清单新增独立“设备动作预检”。先选择一托，沿用该规格当前双叉及底座实测资料。输入设备名称、来源、版本、车体长宽高、门架厚宽和覆盖整段动作的最大高度、该包络覆盖的最大起升量及检查间隙。全部设备尺寸留空；零间隙、零起升范围也须明确填写。一个通过格式校验的设备模板可保存在本机，跨刷新后手工载入；现场、动作和检查结论不自动保存或复用。

车体与门架前缘均位于叉根，向抽叉方向延伸，宽度对齐双叉中心；随整托原 LWH／WLH 映射。车体和最大门架包络始终在柜地板上，起升仅移动双叉与载货。这个规则矩形模型须有实际资料支持，不表示任意叉车形体、真实门架运动学或额定能力。

每次手工指定一个单轴 X／Y 平移，或一个单独起升／下降动作；相同起终点仅检查静态姿态。整托随叉移动和目标整托留在最终位置两种模式分开。拒绝对角与复合动作，不搜索或采样转弯。连续轴向平移的矩形扫掠覆盖两个端点间的全部位置；异形货物、邻托使用保守外包络，因此受阻表示当前保守模型不通过，不能直接断言真实凹槽或曲面必然相交。

## 现场与障碍

输出扫掠 XYZ 使用实际柜头／左壁／地板原点（mm）。备份快照中的原方案仍是可用空间坐标，JSON 明确记录加上 planClearance 的转换。动作 X／Y 为相对所选整托最终位置的偏移，起升量为相对最终底座高度的增量。

门洞宽高沿用柜型，另填门洞左缘、下缘／门槛、门框内外各占深度。门外工作区独立填写长度、左缘、宽度、净高、地面高度与资料来源、版本。门洞只在扫掠碰到门框深度带或柜尾平面时检查；门外矩形从柜尾向外延伸。涉及但缺失的边界保持未核验，尚不支持开放式装载、只打托场地、坡道或门外地面高差。几何间隙用于侧向、顶部及障碍分离，合法地板接触不要求货物或车体悬浮。

检查当前货物、其他完整托盘、柜内障碍、安装预留和所有前装／后装附件，均不删除。未随叉移动的目标托盘按实际包装部件及货物检查进出叉；随叉移动时检查设备相对本托实体部件和货物的干涉。跨托支承货物不能作为可独立搬运的整托检查。

## 状态与交付

单段状态分为保守几何净空通过、保守包络受阻、未核验。缺设备、缺现场、失效叉具证据、不支持动作、起升超出资料覆盖范围单独报告；受阻定位设备部件及货物／整托／区域 ID。资料或方案一旦变更，界面旧结果立即失效，导出前重新计算。

预检不改变箱位、数量、库存、重量、双策略缓存或五项复核。独立 JSON 包含设备、现场、动作、资料、方案身份、原位置快照、坐标转换、当前扫掠与未核验范围。该文件不是工作区备份，也不是可复用授权；本阶段设备任务不写入原工作区、CSV 或 PDF。主方案交付仍使用原五项复核，避免把单段几何通过误作完整搬运通过。

## 两站实际验收（2026 年 10 月 17 日）

- Cloudflare 正式站重新计算默认订单，两套算法均为 116 箱、3,842 kg，布局校验通过，引擎显示 0.37.0。切换默认订单的先打托工作流后，整托清单可打开新预检；设备尺寸为空时结果为“本单段未核验”。验收后恢复直接装柜默认订单。
- Vercel 使用明确标记 QA 的一托小例：SHED 400 × 400 × 200 mm、10 kg、1 箱；另外两个长件不能装入所选托盘，仍作为未装订单保留。两算法均 1 箱、1 托、35 kg，布局校验通过。沿用 QA 底座／双叉资料，表示软件测试，不是实测设备额定依据。
- 手工 X 方向 0 → 13,000 mm 的运动：门框和门外资料为空时未核验；补齐齐平地面、门框及独立门外矩形后，当前单段保守净空通过。将车体宽度 600 改为 2,600 mm，旧结果立即失效且禁止导出旧结论；重算定位车体侧壁与门洞受阻。恢复宽度，门槛设为 50 mm 时明确列出两根货叉受阻。
- 起升 0 → 150 mm：车体包络仍为 500 × 600 × 700 mm、底面 Z=0；最大门架保持 100 × 600 × 1,200 mm、底面 Z=0；叉具扫掠高由 50 增至 200 mm，整托外包络扫掠高为 494 mm。实际下载 JSON 后逐项核对来源版本、方案身份、动作和五个部件扫掠，见[验收 JSON](field-upgrades/evidence/v0.37.0-equipment-action.json)及[实际页面截图](field-upgrades/evidence/v0.37.0-equipment.jpg)。
- 收口时在新的浏览器会话中保存 QA 设备模板，再实际刷新、重新计算，手工载入后名称、版本和全部尺寸一致。英文预检页面与缺叉具资料的结果未见中文残留；设备／叉具资料缺失没有自动通过。删除测试模板后再次载入显示本机没有已保存模板。
- 当前验收浏览器已恢复中文直接装柜默认订单，两套算法均 116 箱、3,842 kg；未保留测试模板。此次收口的应用错误日志为空（不包括浏览器扩展自身日志）。截图与 JSON 留有 QA 测试数据供复现。

上述是软件模型与界面验收。默认订单原有直线门洞路径仍不通过，承重和运输固定未核验；本阶段未改变五项复核结论，也没有取得真实 GPU 或现场设备试装证据。
