# v0.34.0 柜内障碍与禁占区

日期：2026 年 10 月 16 日。基线 GitHub 60675b91789e06bfcea63ed06fc2a66af2a6bfac（v0.33.0）。范围见[计划 007](field-upgrades/007-site-exclusions.md)，完整剩余任务见[Markdown 台账](field-upgrades/unfinished-roadmap.md)。

## 本轮完成

装载配置新增最多 16 个轴对齐长方体区域，可标为固定障碍或禁止占用的预留区。坐标以实际柜内柜头、左壁、地板为原点，单位 mm；求解时转换并裁剪到安全间隙后的可用空间。重叠区域按轴对齐并集准确扣除一次容积。区域不计货物、重量、层数或包装自重，也不能作为承托面。

双策略拼柜与单品容量转入显式避障求解，避免沿用未考虑障碍的快速排布或历史经验标定。预打托装柜检查完整托盘／木箱外包络。独立校验、编辑采用、备份恢复、方案数据核对和现场版本指纹使用相同区域。区域配置无效或覆盖全部有效空间时阻止计算。

空隙分析排除区域；后门直线和有限转向／抬升检查把固定区域保留为阻挡物。开放装载面的绕行及吊装尚未核验，结果保留未核验。三维、降级图、三视图、客户／离线报告与 PDF 保留同源区域；播放或隐藏货物不会删除固定区域，也不把区域当成货物占用长度。报告另列物理坐标，CSV 用 site-exclusion 与 physical-inner 明确区分区域和货物记录。

## 验证结果

`npm run build:pages` 完成：829 项单元测试（71 个文件）、21 项 HTML 结构检查、TypeScript、lint 零错误（3 项既有警告）、Next 静态生产构建全部通过。新增 23 项测试覆盖输入边界、容积并集、双策略、单品容量、整套和整托、真实凹槽、支承排除、路径、备份篡改、报告／PDF／CSV、中英文与永久投影。

固定例：1000×1000×1000 mm 空间、安全间隙 0；500 mm 立方箱每箱 10 kg，需求 8 箱；柜底角部设置 500 mm 立方障碍。可用容积 0.875 m³，两个策略均得 6 箱、60 kg。不能以剩余体积推算为 7 箱：障碍正上方没有合法承托。完整整托的空心内部也不得与区域侵占。

发布通过 main 的现有 GitHub CI、Cloudflare Pages 和 Vercel 自动部署；交付前须分别核对正式域名版本和代表流程。在线验收结果及对应提交随交付提供，不能用本地构建替代在线验收。

## 明确保留的范围

只打托和自动铺底层托盘暂不支持柜内区域，界面与引擎明确阻止该组合；柜外打托预览不应用车辆区域。区域只有空间语义，不计实体材料重量，不代表固定件强度合格。门槛通过、门洞偏置、任意形体障碍、设备扫掠、附件安装动作及地板载荷尚未实现。实体货物的凹槽碰撞仍使用原有经过校验的真实材料／保守代理定义。

真实硬件 GPU、多浏览器和现场试装为 PENDING。降级 SVG 视图通过不替代 GPU。木箱继续按原有规则底置；本轮没有启用自动叠箱，也没有升级依赖。
