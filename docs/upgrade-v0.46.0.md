# v0.46.0 整托与指定散箱同柜

日期：2026-10-20。基线 GitHub `b8d6709376d1bac6ef2b6fb761a5a905c4774f56`，源树 `f940af5aa018de20e684c0123e0adb8f9da2990e`。

“先打托，后装箱”增加按 SKU 预留散装箱数。先扣除预留，余货按现有包装规则生成完整托盘／木箱，再将整托包络与散箱一起求解。默认预留为 0，旧文件仍全部打托；不会因缺包装或装不下自动拆托。

## 本轮范围

- 预留以箱为单位；多箱套装各组成 SKU 必须预留相同完整套数。套装不可跨托，也不能一半打托一半散装；散装套数由原子搜索完整装入或回滚。
- 两种算法共同检查整托外形、散箱真实形体／声明代理、边界、门洞、间隙、承托和总重。散箱可以按自身规则彼此堆叠，首阶段不与整托互相承托，也不占用木箱／托盘内部空隙。
- 独立校验、手动编辑和恢复使用相同分配上限；备份中的预留必须与当前输入一致。清单数量、包装自重、散箱重量、余货和套号各计一次。修复原订单 ID 与内部整托 ID 碰撞的情况。
- 站次／路径检查同时包含完整托与散箱；播放保留整托连续性和散箱自身支承顺序。包装库存用尽的余货继续保留。
- 打托预览先扣除散装预留，只预览其余货物；预留散箱在装柜计算中出现。“只打托”若仍有预留，提示清除或切换，不静默丢弃。
- 中英文界面新增散箱清单：预留、已散装、已打托入柜、未装和散箱重量。CSV 增加装载单元类型，HTML／PDF 增加混装清单，逐箱坐标保留归属。

契约见 [013A 阶段文档](field-upgrades/013a-pallet-loose-mix.md)。这是阶段 013 的首批软件，自动经济尾数、跨柜共享库存／联合方案、拆托重打代价和总成本继续待做；具体叉车操作仍 EXCLUDED。真实 GPU、多浏览器硬件和现场试装继续 PENDING。
