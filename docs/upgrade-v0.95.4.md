# CargoFit v0.95.4 — 标注轨道与恢复草稿辨识

依据上传的 `cargofit_v0_95_3.html`，本轮只处理两个高优先级问题：尺寸文字压线，以及默认演示与恢复草稿混淆。其余报告项留在后续里程碑，不计作本轮已完成。

## 默认演示与旧草稿

报告所列 116 箱与旧版 SAMPLE_PRODUCTS 的 36 / 56 / 24 箱一致；当前 DEMO_PRODUCTS 为 30 / 66 / 48，共 144 箱。这个数量差异支持旧数据来源的判断，但不能据此断言测试者的浏览器状态。

恢复本机草稿后，如果货物不再匹配当前演示，第一步明确显示当前箱数与 144 箱新版演示入口。草稿不自动迁移、不自动改参数；载入演示沿用既有替换确认及先备份提示，取消不替换当前工作。这个来源提示仅是页面状态，不新增备份字段。

当前宽托演示在两种算法下均装入 144 箱、重心平衡，独立装卸路径复核通过。承重和运输固定资料缺失仍保持未核验，不能为了“全绿”展示而标为通过。

## 尺寸文字与蓝线

- 标题优先留在测量边外侧；窄画布或大字号无足够空间时，使用模型外围的可用轨道与绕开模型的引线。
- 可见蓝线在所有尺寸文字及刻度周围保留 10 px 安全区。物理测量边、刻度采样点和毫米值保持原样。
- 开启尺寸时，相机初始构图预留标注边距；保持真实模型中心、比例与测量值。WebGL 与 CPU 降级视图共用投影布局及边距规则。
- 自动构图用于初始、重置和视口变化；极端手动放大、硬件 WebGL 画质及真实设备性能仍需实机验收。

## 自动验证

- 完整 `npm run verify`：190 个测试文件、2305 项单元测试和 21 项页面检查通过。
- 类型检查及 lint 无错误，保留两个既有 lint 警告。
- 新增回归覆盖旧 116 箱与当前 144 箱的区分、演示路径/重心与未核验状态、320–960 px 画布中 14/18/22/26 px 字号的标注间距，以及真实相机控制器的标注边距和自由视角不重置行为。
- 云端 API 打包和直连/重写路由检查通过。
- 浏览器实测：1440×900、1280×800、768×1024、390×844 的中英文 Step 1 页面均无横向溢出；薄托盘 Step 2 的 26 px 字号、Step 7 桌面与手机俯视标注及桌面三视图可读。测试浏览器未启用 WebGL，不能将降级视图实测称为 GPU 画质验收。
- 使用真实界面构造 36 / 56 / 24 共 116 箱草稿并重新载入：来源提示正确；英文取消替换仍为 116 箱，确认载入后为 30 / 66 / 48 共 144 箱。未声称重现报告测试者的完整历史状态或 76 箱结果。
- 完整七步浏览器操作：现场与高密度均装入 144 箱；现场方案毛重 4811 kg、重心 40.2% / 46.5% / 37.0%，路径通过、承重与运输固定未核验。
- 正式部署结果与线上版本在 PR 记录中跟踪。

## 不变与未完成项

求解器只更新展示版本号；碰撞、载重、承重、装卸路径校验与工作区格式不变。正式安全头与完整构建检查保持原样，视口测试页面和专用嵌入配置仅存在于独立 QA 分支。

报告中的多柜弹窗嵌套边框、Step 4 三栏折叠态对齐、商业官网和全局单位切换不属于本轮两个模块，尚未据此宣称完成。GitHub Actions 启动故障与硬件 WebGL/真实手机验收也不作为本轮通过项。
