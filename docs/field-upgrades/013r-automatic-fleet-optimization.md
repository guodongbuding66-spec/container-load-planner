# 013R 自动整单优化：五轮交付第 1 轮

在已运行当前设置整单分配后，新增统一的“自动整单优化”。旧单组／2–4 组工具保留在手动比较折叠区，原版本 1／2 报告格式不改。

## 自动搜索及货量

自动建立最多 64 个稳定源行／完整套装决策，按完整套数增加原有全单散箱配额；同名 SKU 保留源行 ID。原订单、包装规格、各规格库存、总托数、柜型可用数和既有配额下限不改变。可比较现有列表顺序与紧凑包装选择，不生成虚构规格或额外库存。

小网格在本轮新增箱数上限内完整枚举；较大范围从整单尾数、各量级多组和单侧候选出发，围绕独立复核的最佳向量进行自适应邻域细化。每批最多 64 个完整候选、64 箱新增散箱、4000 箱原订单、20 柜和 30 秒。报告分别记录完整网格或有界自适应、候选域上界、已评估个数及全部分配向量；不把有界结果称为一般全局最优。

每柜与整单库存、费用、源行账本重新校验，任何原始源行已装量减少的候选不能采用。先保留原行、比较已装量，再按当前柜数／完整配置费用目标；同结果优先较少新增散箱。未知费用不按 0 比较。

## 保留已装柜

用户可保留前 N 柜。整单重排模式中，已有封存上下文、交付身份、锁定或实测单元决定最小保留前缀。前缀保留完整原方案 ID、箱托 ID、坐标、朝向、锁定、实测及交付身份，不重新打托。

`FleetLoad.frozen` 保存该柜形成时的全单散箱配额和包装选择。独立校验按该上下文恢复其局部输入，同时按当前全单真实箱数、包装库存和配额重新扣账；旧配额不得超过新配额，封存柜必须是连续前缀。新配额只作用于未封存部分。普通全单重新生成入口不覆盖已保留／锁定柜。

含该上下文的多柜备份使用既有格式标识加 `version: 2`；无封存上下文继续为版本 1。旧版本 1 文件仍可恢复，版本 1 不可偷偷携带新上下文。旧手动重排拒绝封存柜，不能绕过前缀保护。

## 在原位置补余货

“只补现有柜空隙”保持所有原箱位与完整托盘的位置、身份及内容，不拆托、不新增包装，也不增减现有柜。封存／已交付柜仍完整保留；其他原锁定、实测单元可作为固定占位，但不会移动或改变托内内容。

仅从原订单尚未装入且未被后续原箱位占用的数量中，追加完整散箱／套装。逐柜用真实整托保守包络、原有散箱、禁占区、门洞、载重、间隙及支承规则搜索；散箱不得进入托内空洞或与整托互相承托。每个候选最终恢复完整预打托方案再独立校验。整托补入、跨托接触和更多几何能力继续在第 2 轮；不把当前散箱功能核销全部 U11。

## 本次拆托与重打费用

整单重排按未封存部分原实际入柜托数计拆托、按候选实际新托数计重打；重排范围内的单元均作为重打工作计费，不以坐标偶然相同推断实物复用。前缀不计新工作，仅补空隙的两项数量均为 0。

两项单价各自明确报价，免费须勾选并填 0；已报价必须有来源。未知工作量单价会令候选完整费用未知，费用目标必须补齐。派生的本轮工作费按订单项追加到既有报价账本，以实际数量重新计算，连同包装及运费进入多柜汇总、备份和导出；保留原有报价，不覆盖已有工作费。不是税务结算或工厂实际工资凭证。

## 复核、采用与报告

线程初始化一次，每次只计算主线程明确提交的下一个向量；独立复核通过后才继续。只保留候选摘要及当前最佳完整几何。错误、停止、输入或报价改变、重跑、卸载及超时全部使旧导出／采用回调失效，消息到达时也核对截止时间。

新 JSON 为 `cargo-fit-fleet-optimization` 版本 1，保留未采用标记、完整来源、设置、搜索范围、所有候选向量、源行、实际工作数量与费用和最佳多柜方案。CSV 每个候选包含所有原始源行。采用时重建搜索调度并核对完整候选记录，拒绝截断但伪造已完成标记的报告，重新核算派生费用并独立验证最佳几何与全部固定前缀。

明确采用后保留完整多柜方案、配额及报价，并按全单配置独立重算主柜。固定承诺针对完整多柜方案；主柜是独立求解的参考方案。工作区保存输入与主柜，全部柜须另存多柜备份。

发布、测试、双站原件和剩余范围以 [v0.77.0](../upgrade-v0.77.0.md) 和 [五轮计划](../five-release-plan.md) 为准。
