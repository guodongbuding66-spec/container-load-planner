2. 锁定是编辑约束，当前登记签名变化后明确发布下一版。在原计划发布下一版前，检查本机已有或本页尚未成功缓存的现场记录：任何已装单元的位置、朝向、规格、归属或已装托的组成发生变化，阻止发布。必须先在原版本明确撤回并填写实际原因。复制为新计划仍产生独立身份，不宣称继承原实物。
3. 新版本由用户明确导入同计划直接上一版的现场文件并填写迁移原因，不能跨计划、跳号或猜测分支关系。已装位置必须完全保持；未装的缺损状态只在编号和物理规格可确认时继承。带现场状态的撤出单元不得静默丢失。

5. 新版已有现场事件时，迁移追加来源事件而不覆盖：同单元并行结果保留冲突，再明确处理。独立生成的不同迁移来源不自动拼接，要求各设备先使用同一份迁移备份。相同来源的同版本分支继续去重合并。
6. 完整包最多八次迁移历史、50 MB；不截断旧记录来冒充成功。迁移事件、状态、原因、来源头、历史关系或父版本不一致时拒绝导入。旧缓存只读兼容，新缓存单独按计划／版本保存；故障时先导出原始数据再重新开始。

## 边界

这是本机已知现场记录的保护流程，没有云端锁、账号权限或全局实物库存。跨设备编辑前必须先导入最新现场文件；本机没有记录不能解释为货物尚未装。整单重新求解仍是独立未登记候选，不猜原实物继承。跨柜身份、拆托替代、包装实际缺货替换、经济尾数及预打托联合自动重排继续待做。实际显卡、打印扫码、强度额定资料及现场试装不由软件样例代替。

## 备份失败恢复

版本与完整现场包可明确显示只读 JSON 全文，便于浏览器下载失败时复制保存。版本备份仅在有效、已登记且当前的方案中显示；草稿不通过文本导出绕过发布拦截。现场文本保留历史与照片，损坏缓存先走原始数据恢复。发起下载不宣称文件已保存，仍需核对实际文件或使用文本备份。
