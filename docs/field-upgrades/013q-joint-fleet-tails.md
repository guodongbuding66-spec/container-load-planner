# 013Q 多组尾数跨柜联合比较

状态：首阶段软件、GitHub CI、双站正式发布及原生中英文验收完成；U09／U10／U11 继续 PARTIAL。

在“整单多柜分配与费用比较”完成当前整单分配后，尾数工具新增“2–4 组联合比较”。每组为一个稳定源订单行或一整个套装，同名 SKU 继续显示源行 ID。各组上限表示在原全单散箱配额之上增加的箱／套单位。

完整枚举每组 0 至上限，排除全零向量；因此单侧变化与全部选中组同时变化均在比较内。完整组合最多 64 个，所有组新增箱数上限之和最多 64 箱，超过时拒绝而不暗中截断网格；原单仍限 4000 箱、10 柜，整批预算 30 秒。四组各 1 为 15 个候选，三组各 3 为 63 个，四组各 2 的 80 个组合会被拒绝。

候选保留原订单、套装比例、各包装规格库存、总托数上限、柜型可用数、已有散箱预留与报价。每柜坐标及整单库存、余货、费用都经过独立校验，所有源行的已装数量不得减少。先比较货量，再按已选择的柜数／费用目标排序；实际结果相同时保留新增箱数较小的向量，再按组顺序稳定排序。未知报价不当作免费。

计算线程每次仅求解一个候选，主线程独立校验成功后才请求下一个。界面仅保留候选摘要和当前最佳方案的完整坐标，避免同时保存最多 64 份完整多柜几何。停止、超时、无效回复或失败批次不可导出或采用；消息抵达时也检查截止时间，不能因计时回调尚未执行而采用迟到结果。

候选表显示各组的新增向量、合计新增箱数、实际柜数／装入量／余货／包装／散箱／配置费用及逐行保留结果。选中候选继续展示所有原始源行。只有明确采用才更新全单配额，原有主柜重算及完整多柜方案衔接沿用同源校验。

联合报告使用 `cargo-fit-fleet-tail-preview` 版本 2：包含每组 ID、名称、单位箱数及上限，所有候选的完整分配向量和所有源行，保留未采用标记。CSV 在既有候选源行列之后追加合计新增箱数和逐组新增单位列。单组快速比较继续输出版本 1，列格式保持兼容。

新增 27 项测试：四组双策略共享库存、第四组相对三组的独立改善、完整网格、63／64 组合边界、完整套装与非整套余量、合计箱数预算、同名行、报告向量、流式复核和采用元数据、线程逐步确认，以及第四组／模式往返失效和计时回调前的迟到消息拒绝。

原生验收补充：修复从无效数值草稿切换搜索范围后，已重建的有效输入仍被旧有效性标记锁住的问题。两站均验证模式往返恢复可预览，原报告仍失效；80 组合拒绝、第四组往返失效、完整采用、库存与费用、跨站坐标逐字节一致和刷新保持通过。10 项界面断言、20 项文件复核及两站各 20 次固定基准原件已归档。

未完成：五组以上、启发式自适应配额、固定已装前缀的局部优化、实物包装身份、拆托重打成本及更广全局搜索。真实 GPU 与现场试装独立待验收；具体叉车动作仍排除。发布与原生证据见 [v0.76.0](../upgrade-v0.76.0.md)。
