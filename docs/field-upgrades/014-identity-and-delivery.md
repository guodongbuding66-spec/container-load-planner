## 实施顺序

1. 014A 稳定订单行：SKU 是业务属性；不同客户、批次及站次允许相同 SKU，继续使用独立订单行 ID。编辑、复制、导入及合并必须明确新增还是修改，不能仅按 SKU 自动合并。已有产品 ID 和旧文件可读，不给缺失资料猜客户或批次。
2. 014B 实物身份：在源订单与方案内分别保存货箱、整托及包装规格的稳定 ID；柜号和局部可视化编号只用于显示。重排、转托、尾柜替换保留可确认的实物 ID；拆托或重建须明确废止及替代关系。不会把候选预生成包装伪装成已制作包装。
3. 014C 逐托交付：二维码引用 planId、revision、unitId 和包装版本；按当前版本打开货物与分层清单。复制方案产生新计划身份，旧版本扫码给出明确状态。
4. 014D 现场变化：记录防重扫码、缺箱、损伤、包装缺货及已装确认；事件具有稳定 ID、时间和来源。锁定已装区域后，仅对剩余货物重排；冲突定位后由用户处理，不静默改动已确认实物。
5. 014E 离线与冲突：离线事件可导出／导入和去重；先做单工作区可追溯流程，再定义多人同步，不能用本机缓存宣称多端一致。
