# 014A：稳定订单行与客户、批次资料

状态：DONE（首阶段软件），v0.48.0；基线 v0.47.0。具体叉车作业 EXCLUDED。

- 沿用产品 id 作为源订单行身份；SKU 是可重复的业务属性。订单编号、业务行号、批次、客户、目的地及卸货站次随行保存，不把业务行号当内部 ID。
- 编辑资料保留 ID。复制普通行创建新 ID；复制套装必须连同全部组成行，生成新套装编码，清空业务行号及外部来源引用，需求箱数也一同复制。
- 导入明确区分替换、追加及按 ID 只更新数量。旧模板无 ID 时仍生成新行；提供 orderLineId 可保留源行身份。追加总是生成新 ID，套装编码若与既有订单冲突则拒绝，避免合并 BOM。
- 数量更新仅采用 orderLineId 和 quantity，拒绝未知或重复 ID；忽略文件中其他列，保留所有箱规、客户、批次、来源和包装规则。允许数量 0，行身份保留；不能小于指定散箱预留。
- 替换若会移除包装白名单、散箱配额或固定附件的订单行引用，整次拒绝，要求保留原 ID 或先清除关联。不静默扩大包装适用范围。
- CSV 与 Excel 使用相同验证。有订单资料或同 SKU 多行时，坐标 CSV 末尾追加源订单行 ID、订单编号、业务行号及批次，不移动旧列。订单行 CSV 可供数量更新和新单导入；完整来源、包装版本及全部工作区规则继续以 JSON 备份交付。
- 客户、批次及站次进入源数据和方案同源校验；从旧结果采用站次时同步回源订单，重新计算不丢失。客户／离线报告和 PDF 增加独立订单行清单，区分同 SKU。
- 旧工作区继续读取；重复源行 ID 和矛盾站次拒绝恢复。各柜继续按原订单行保留数量、套装和静态路径资料；站次没有参与新的几何优化。
