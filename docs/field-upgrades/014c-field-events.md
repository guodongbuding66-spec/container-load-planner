# 014C/D/E 首阶段：箱托交付标签与离线现场事件

状态：DONE（本节首阶段软件与双站实际验收，v0.50.0）；014 全阶段仍为 PARTIAL。前置 014B1 已通过双站验收。具体叉车操作 EXCLUDED。

## 本轮完成条件

- 已登记且与当前箱位一致的版本，才能进入现场登记。扫码只选中箱或托，核对后明确确认实装；不使用指导书游标充当实装记录。
- 每箱／每托独立二维码，引用 planId、数字 revision、revisionId、变更摘要及 unitId。二维码只有编号，没有货物、客户、照片和登录凭据；放在 URL fragment 内，不作为服务器查询参数。另一个设备需先恢复匹配的工作区备份，打开现场面板后核对二维码。
- 本单元标签 HTML 含二维码、版本、外尺寸、计划重量、箱号、SKU、源行、绝对坐标和分层清单，可离线查看与打印。整托包含单一归属的预打托货箱；柜底铺托只确认托盘自身，不推断上方货物实装。
- 确认装载、撤回装载、缺箱、损伤、清除异常、冲突处理都追加独立事件 ID、设备来源、设备时间、备注、照片和各原子单元的来源事件。原事件不覆盖。照片仅在本机及手动导出 JSON 内，不自动上传；每事件最多三张 PNG/JPEG/WebP，各不超过 1 MB。
- 已装确认可与损伤并存；缺箱不能同时为已装。缺箱须先处理异常才能再次确认。撤回已装或改成缺箱必须有原因。相同状态重复确认不增加数量；整托确认按箱／包装原子 ID 计数，单箱重复登记不双计。
- JSON 保留完整事件、因果来源、照片和版本；CSV 每个受影响单元一行，保留事件关联及照片名，不能代替完整 JSON。保护公式样式备注。工作区备份不包括事件，界面明确要求单独备份。
- 本机缓存按计划及独立版本 UUID 隔离。存储失败保留当前页面事件，提示立即下载，不能宣称已保存。损坏旧缓存先下载原始数据再开始空白记录，避免静默覆盖。
- 离线导入要求完全匹配的版本、箱位和原子清单。相同事件 ID 相同内容去重，不同内容拒绝整次导入；独立箱体的事件正常合并，同一箱体并行分支保留冲突，不按设备时间或最后写入猜结果。冲突单元不计已装或缺损结论，必须填写原因后明确处理；再次导入旧分支不恢复已处理冲突。
- 读取上限：20,200 个单元、50,000 个事件、50 MB JSON；父事件缺失、循环、自引用、伪造状态转移、重复单元、非法日期、非法照片和原型字段拒绝。内容校验不是数字签名、权限管理或真实性认证。

## 验收

核心需覆盖旧版本、复制版本、重复扫描、整托／柜底铺托差异、缺损、照片、反转、并行分支、乱序输入、损坏文件和重导去重。界面需覆盖中英文、空状态、损坏本机记录的可恢复流程及明确版本门槛。完整现有回归、类型、lint 和生产构建通过后，再进行两正式站事件导出、跨站导入、去重、旧版二维码拒绝、标签与分层清单核对。

## 实际交付证据

1,328 项单元测试（101 个文件）、21 项页面检查、TypeScript、lint 与生产构建通过；核心及 UI 专项 28 项。两正式站以同一 v2 交付方案验证：重复确认只计一箱；已装损伤可并存，照片保存在导出 JSON；无原因撤回被拒绝；英文旧版本二维码被拒绝；另一站的缺箱分支合并产生明确冲突，处理后四事件去重并双向一致。另在正式站登记两层八箱整托，一次确认产生九单元的一条事件，总计划重量 105 kg；重复确认不增计，标签保留全部八箱和 544 mm 总高。
