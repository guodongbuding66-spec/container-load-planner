# 013A：整托与指定散箱同柜

状态：软件实现及本地全面验证完成，线上验收待完成。阶段 013 的第一批；跨柜共享库存与总成本另行继续。

## 本次契约

- 在“先打托，后装箱”内按订单行明确填写预留散装箱数，默认全部为 0。先从订单扣除预留，再生成整托；不因空间不足、包装缺货或装不下而自动拆托。
- 多箱套装各组成 SKU 必须预留相同的完整套数；每套要么在同一完整托上，要么全部散装在同柜，不能一半打托一半散装。散装套数允许装不全订单，但不能装半套。
- 将完整托／木箱外包络与预留散箱共同求解。散箱可以按自身规则彼此堆叠；首阶段不允许散箱与整托互相承托、桥接，也不能钻入整托／木箱包络内部。包装与货物保护间隙都必须保留。
- 只打托模式不接受散装预留，保留配置并提示用户清除或切换；旧文件缺少此字段仍全部打托。
- 独立校验、手动编辑、恢复、两种算法、库存、数量、成套、重量及导出使用相同规则。预留散箱不能被打托，未预留的箱数不能被散装；未装货量继续保留。
- 路径／站次检查同时包含完整托与散箱。清单列出预留、已散装、已打托、未装数量；坐标 CSV 明确标识装载单元类型，HTML／PDF 一并交付。

## 验收与边界

覆盖同 SKU 混装、完整套装、缺货、散装堆叠、整托保护间隙、木箱空腔隔离、重量和门洞超限、旧文件兼容、篡改恢复及双站中英文。完整构建和线上证据在 v0.46.0 交付记录补齐。

本阶段使用用户指定散箱数量，不自动判断经济尾数；不自动拆托补货、不做跨柜联合最优、不同装载方式互相承托或具体叉车操作。实际 GPU 验收仍待真实硬件，不以坐标视图冒充。
