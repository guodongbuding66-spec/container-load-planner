# 013E 原订单托内限高诊断

状态：v0.64.0 软件、完整检查、GitHub CI、双站发布和受控案例原生验收完成。原截图完整输入未取得，原始问题保持待复现。

1. 展示各规格当前托内净高、柜门允许净高及 SKU 的单独上界；订单未完成、只生成首层时明确提示，不把整托不叠放解释成纸箱只能一层。
2. 用当前订单直接预览提高开放式托盘限高，保持数量、库存、载荷、朝向、底置与承托规则。木箱、零库存、不适用 SKU 的规格不自动修改。
3. 预览与采用分开；只允许采用比当前方案多装的已校验候选，再正式重算两策略并保存。已有交付版本只预览，实测包络禁用标称试算。
4. 运行中可停止，30 秒超时、参数变化和旧响应丢弃。原订单与结果不会被预览覆盖。

验收案例见 [v0.64.0](../upgrade-v0.64.0.md)。专项需覆盖大订单 596→16→92、两策略、约束保留、木箱及库存、多规格、独立拒绝相交结果、参数过期、取消、超时、交付与实测保护。随后完整 lint、类型、单元、页面与生产构建，再同步 GitHub 与双站，验收正式重算、刷新及原生备份。

未完成：原用户工作区精确复现；更广包装尺寸联合优化；跨托已装位置保持的补货；真实 GPU 和现场证据。不能用提高限高保证货物承重或运输稳定性。
