更新日期：2026 年 10 月 17 日。初始核查基线：v0.33.0，GitHub 60675b91789e06bfcea63ed06fc2a66af2a6bfac；当前软件实现 v0.37.0。

本文件是剩余工作台账和后续实施顺序。用户已授权按文档逐步升级、执行全面测试、同步现有 GitHub 与 Cloudflare Pages、Vercel 网站；常规阶段内继续执行，无需反复确认。此授权不补足实际结构额定资料、设备参数或硬件 GPU 证据。每次交付只把实际完成并验证的项目改为完成，其余继续保留。

状态：TODO 未实现；PARTIAL 部分实现；PENDING 待外部数据或实机验收；DONE 已实现且有对应软件验证。软件测试、真实 GPU、现场试装分别记录。

## 已有能力与避免重复建设

三栏工作台、侧栏宽度及偏好、两点／两箱／柜壁测量、点边面外包络捕捉、精度和锁定、剖切隔离、多选移动与撤销已有实现。规则异型件、自定义截面、组合件、GLB／glTF 导入、保守代理碰撞、平面承托和防滚声明已有基础。

v0.28.1 已统一五项复核及真实投影交付；v0.29.0 已增加托内编辑、层复制、跨托转移和锁定；v0.30.0 已增加实测尺寸、随箱附件增量及标称／保守双方案；v0.31.0 与 v0.32.0 已增加木箱资料、四角实体路径及独立叠放预检；v0.33.0 已增加逐托包装候选比较和尾数小包装选择。v0.35.0 已增加规则底座实测、同源贯通净孔及独立双叉进出预检，资料来源和三类载荷分别保存。v0.36.0 已增加独立整柜附件包络、计划重量、材料清单和安装依赖。v0.37.0 已增加车体、最大门架、双叉与载货的独立固定朝向单轴动作预检和门外边界。木箱自动叠放、完整设备搬运和运输固定强度不能据此视作完成。

## 自动实施顺序

1. **阶段 007 柜内障碍与禁占区**：先支持有界轴对齐区域。同步接入求解、独立校验、空隙、路径与交付；不支持的工作流组合必须明确阻止，不静默忽略。门框门槛的专门参数和任意形体障碍留给后续子阶段。
2. **阶段 008 叉孔及实测结构**：实际孔位与包装模型同源，增加进叉和抽叉几何预检；设备能力未知与几何失败分开。
3. **阶段 009 整柜附件及固定预留**：空间、重量、材料清单与作业依赖，先手工记录和确定几何，再开展有资料的固定核查。
4. **阶段 010 设备动作检查**：采用已确认设备模板；保留快速货物通道模式，增加设备扫掠、受阻步骤和未检查范围。
5. **阶段 011 托内层型、长件承托和局部重排**：先层型事务，再接实测悬跨与受力条件。
6. **阶段 012 木箱自动叠放**：等待实际有效结构额定资料；可先补算法及未知状态测试，资料不全不启用生产叠箱。
7. **阶段 013 整托散箱、跨柜库存与成本**：保持完整交付和包装库存守恒，比较完整方案，公开目标与搜索范围。
8. **阶段 014 身份、逐托交付与现场变更**：稳定订单行和实物身份先行，再扫码、防重、离线异常及版本冲突。
9. **阶段 015 载荷、公差、模型和测量深化**：分别实现独立数据契约和验证，不合并为单一“安全通过”。
10. **阶段 016 核重、防潮和作业管理**；**阶段 017 算法基准与质量看板**；道路轴荷和高阶物理独立立项。

U01 的实机验收随各阶段持续进行。环境缺少实际硬件或设备资料时记 PENDING，继续不依赖这些证据的软件工作，不用示例额定值、SVG 或软件渲染冒充现场验收。

## 每阶段交付门槛

- 开始前核对 main 提交、工作区变更和本阶段范围；不覆盖其他人的改动。
- 修改共享输入、求解、独立校验、编辑、备份和导出时检查同源性；保持 mm／kg，现场间隙与数值误差分开。
- 增加有实际边界意义的回归：有效场景、超限、缺资料、旧文件兼容、篡改恢复、订单／套装／重量守恒和中英文。
- 执行 `npm run build:pages`，其中包含 lint、TypeScript、完整单元测试和 HTML 结构检查。新增修改后按影响范围追加检查。
- GitHub 与本地树一致，使用预期提交保护更新 main，检查 CI、Cloudflare Pages 和 Vercel；分别访问两个正式域名验证版本及关键流程。
- 发布记录写明实际测试数量、部署提交、线上结果、限制和 PENDING 项。每次恢复测试草稿，避免把临时验收货物留给用户。
- 硬性失败阻止采用与现场交付；资料缺失保留未核验。模型通过不替代设备能力、材料强度或现场试装。
