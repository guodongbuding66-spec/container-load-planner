## 2026-10-18 范围调整

用户明确：具体叉车如何装卸不属于本工具职责，现场情况更复杂，停止这部分功能，继续剩余装柜功能。U05 与 U03 的具体叉具操作从后续开发移出，不再推进转弯、进叉、起升、抽叉、设备能力、坡道及整套施工动作。主界面移除逐托进叉／设备动作／连贯搬运入口与叉具参数；历史任务和原始资料仅保留文件兼容，不扩展或自动作为装柜依据。

继续保留并完善：托盘／木箱真实结构、尺寸与载荷资料；货物是否能装入、门洞净空、装卸站次、货物碰撞和承托；托内编辑、数量及套装守恒、包装库存、余货、公差、费用和现场清单。具体叉车车身、货叉、转向与操作过程不再建模。

## 自动实施顺序

历史 007 柜内障碍、008 底座实测和 009 整柜附件的已完成内容保留；008 的具体叉具操作与 010／010B／010C 的叉车动作后续范围按用户要求移出。

1. **阶段 011 托内层型、长件承托和局部重排**：先完成层型模板和完整事务，再接长条箱支承区、实测悬跨及受力条件，之后在锁定其他整托的条件下局部重排。
2. **阶段 012 木箱自动叠放**：依赖有效结构额定资料；资料不全仍底置，可先补算法及未知状态验证。
3. **阶段 013 整托散箱、跨柜库存与成本**：完整交付、包装库存和套装守恒；比较完整方案及费用。
4. **阶段 014 身份、逐托交付与现场变更**：稳定订单行和实物身份，再扫码、防重、离线异常及版本冲突。
5. **阶段 015 载荷、公差、模型和测量深化**：容器地板与货物支承继续；叉车轮压和运动模拟排除。
6. **阶段 016 核重、防潮和作业管理**；**阶段 017 算法基准与质量看板**；道路轴荷和高阶物理单独排期。

U01 的实机验收随各阶段持续进行。环境缺少实际硬件或设备资料时记 PENDING，继续不依赖这些证据的软件工作，不用示例额定值、SVG 或软件渲染冒充现场验收。

## 每阶段交付门槛

- 开始前核对 main 提交、工作区变更和本阶段范围；不覆盖其他人的改动。
- 修改共享输入、求解、独立校验、编辑、备份和导出时检查同源性；保持 mm／kg，现场间隙与数值误差分开。
- 增加有实际边界意义的回归：有效场景、超限、缺资料、旧文件兼容、篡改恢复、订单／套装／重量守恒和中英文。
- 执行 `npm run build:pages`，其中包含 lint、TypeScript、完整单元测试和 HTML 结构检查。新增修改后按影响范围追加检查。
- GitHub 与本地树一致，使用预期提交保护更新 main，检查 CI、Cloudflare Pages 和 Vercel；分别访问两个正式域名验证版本及关键流程。
- 发布记录写明实际测试数量、部署提交、线上结果、限制和 PENDING 项。每次恢复测试草稿，避免把临时验收货物留给用户。
- 硬性失败阻止采用与现场交付；资料缺失保留未核验。模型通过不替代设备能力、材料强度或现场试装。
