# 013P 整单多柜尾数与共享库存

状态：首阶段软件完成；U09／U10／U11 继续 PARTIAL。

原整单可能因为整托外占位及预留散箱数量而多出尾柜。新入口位于“装载优化 → 整单多柜分配与费用比较”，先完成当前设置的整单分配，再选择一个源订单行或完整套装，预览全单散箱配额的有界增加。

每个候选重新分配整张原订单；柜型库存、包装各规格库存、包装总上限和散箱配额均跨柜共用。原订单数量不增加，旧散箱预留为下限，套装按完整比例增加。每柜坐标、余货、库存、报价及费用均经过独立复核，所有源订单行已装数量都不得减少。先比较装入货量，再按当前柜数／费用目标排序；相同结果保留较小新增配额。报价不完整时不据此声称费用改善。

每批试算 1、2、4、8 和用户上限，去重后最多五个候选；全单新增散箱最多 64 箱，原单最多 4000 箱、10 柜，30 秒批次预算。超时、取消、失败和不完整批次不可采用。已交付、锁定、实测整托方案拒绝重新打托。修改报价、柜型数量、目标、上限或源方案后，旧预览、旧导出及采用回调失效，包括改回原数值。

预览显示每个候选的柜数、装入量／余货、实际包装／散箱、配置总费和逐行保留结果，选中候选显示所有源订单行。只有点击“采用整单尾数并更新工作区”才写入全单散箱配额。主柜双策略重算，多柜面板跨主输入更新保留已验证的完整方案、报价、库存和柜型设置。须单独保存多柜备份；工作区备份保存输入及主柜，不冒充全部多柜坐标。

独立尾数 JSON 保留基线、全部候选源行和选中完整方案，并标记 `preview-not-applied`；CSV 每候选每源行一行。多柜备份与全柜坐标／库存费用 CSV 继续使用现有校验及文件格式。

37 项新增测试覆盖双策略、共享库存、完整套装与非整套余量、同名源行、实际逐行减量拒绝、缺报价、伪造坐标／库存／费用、锁定／实测／交付保护、输入衔接、超时／取消／迟到回复和往返失效。发布及原生文件证据见 [v0.75.0](../upgrade-v0.75.0.md)。
