# 装柜智算现场化升级需求与验收方案

版本 1.0　2026 年 10 月 15 日

本文件保留 v0.28.0 的审查基线；后续实现状态见 [实施索引](README.md) 和 [v0.28.1 验收记录](../upgrade-v0.28.1.md)。

面向工具房、车棚等长条箱和多箱套装业务，供产品规划、算法开发、三维交互开发和仓库试装共同使用。

## 01 升级结论

下一阶段建议先完成交付一致性、托内编辑和现场尺寸管理，再增加木箱承载、搬运设备路径及运输固定。现有版本已经具备多规格包装、实体异型件和三维工作台的基础，应在这些模块上补齐现场约束，避免重复开发入口。

优先交付四项可观察的结果。第一，用户打开任意方案，能立即分清几何、承重、搬运和运输固定各自的校验状态。第二，调整某托的一层货物后，其他锁定托盘保持不动，清单、重量和导出同时更新。第三，标称尺寸与保守尺寸方案可以并排比较，并指出导致少装的具体箱位或门洞。第四，每个被推荐采用的装载单元都有明确的装入和卸出条件。

本轮文档冻结基线为仓库 main 的 2fc3e2c0b6cab37eef5313b8600e41a45b4ab056，引擎版本 v0.28.0。仓库对应的最近两次工作流均成功；其验证范围包含静态检查、单元测试、HTML 检查和 Pages 构建，不包含真实 GPU 多浏览器验收。[E01]

Vercel 线上默认订单已完成一次浏览器抽查：36 箱 SHED-101、56 箱 BED-205、24 箱 PARCEL-310，两种策略均返回 116 箱。页面同时提示 102 个受压箱体缺少该朝向的承重资料。当前检查浏览器采用无 WebGL 的俯视降级视图，不能据此确认透视旋转、透明排序和 GPU 截图已经验收。Pages 已核对入口可访问；两个域名的精确构建提交仍应纳入发布记录。

## 03 真实装柜照片的观察与需求推导

已实际查看以下三组公开现场照片。照片用于识别结构、包装和作业细节；没有根据像素估算尺寸、重量、材料强度或判定照片中的装载合格。需求是结合画面与现有代码作出的产品设计推导。

### 木箱与纸箱混装

照片 P1 来自 Jetfast Bali Cargo 的拼柜现场。近门区域可见不同尺寸的木箱、木条框架、底部托脚和箱顶标签，深处可见不规则纸箱堆放。[P1]

画面说明“木箱外尺寸”需要包含加强条、底座和箱盖的最外侧；只录围板净尺寸可能低估占位。木箱和后排纸箱的卸出条件也不同。建议建立外形尺寸、内部净空、叉孔、允许受力位置四套关联参数，并允许按订单行绑定包装规格。

照片中不能看到的内部支承和木材额定值仍然属于未知。即使两个木箱顶面看起来平整，也不能自动允许叠箱。

### 长件层间垫木与外部木箱

照片 P2 来自 Pingtai Machinery 的实际出货页面。左侧为多层细长构件与间隔木条，外面有薄膜和竖向捆扎；右侧为带外部加强结构的木箱，前后货物高度不同。[P2]

对工具房和车棚长条箱，建议支持按位置布置垫木或横梁、限制最大悬跨，并明确这些部件是否承担上层重量。将垫木和薄膜算入高度、自重和碰撞后，还要说明先铺哪根垫木、何时打带、装入后能否抽叉。照片无法证明货物实际抗弯强度，跨度限值必须来自包装或货物资料。

### 缠绕膜气袋与柜门口绑带

照片 P3 来自海力物流的包装说明页面。可见缠绕膜包裹的成托纸箱、中央填隙气袋和横跨柜门口的交叉绑带。[P3]

由此建议将一部分几何空隙标成“固定材料预留”，并将安装绑带、放置气袋和拆除固定件加入顺序。软件应解释某空隙用于保护或作业的原因，避免补货建议覆盖固定空间。该照片只证明这些材料占有位置，不证明绑带数量、气压或绑点能力满足某一运输条件。

### 装柜资料补充出的检查项

IMO 的 CTU Code 覆盖装载和固定，并说明其为非强制性的全球实践指南；它适合用来组织检查项目，具体适用规则和设备额定值应按运输任务确认。[S1]

Hapag-Lloyd 装柜资料提示应考虑门洞、载荷分布、包装堆叠和固定，并展示垫木、气袋和木箱案例。该资料版本较早，本项目只采用其问题分类，不将其中数值硬编码成通用现行限值。[S2]

Hapag-Lloyd 当前柜型页面明确说明规格为示例，不同制造商柜体可能不同。产品应支持把预设参数替换为本次实际柜号的实测参数。[S3]

IMO 的 VGM 说明列出货物、包装、托盘、垫料与固定材料以及柜体皮重的核重关系。软件的计划重量和实际核重记录需要分栏保存，不能把计算值直接命名为已验证重量。[S4]

## 04 更接近现场的装载约束

### 实际空间与柜门

柜体除长宽高和门洞外，增加门槛高度、门框厚度、门洞偏置、侧壁或立柱凸起、地板不可用区域及门内固定区。冷藏柜还要表达设备凸出和明确的货物边界。视觉模型与求解障碍物分别保存，只有被指定为物理障碍的几何才扣除净空。

到柜后记录柜号、实测净空和数据来源。实测变化触发复核，系统标出受影响的托盘、边界和装载步骤；已经确认的现场作业不能被后台重新计算无提示覆盖。

### 纸箱鼓包与长条箱偏差

每个 SKU 增加标称尺寸、批次实测尺寸、保守增量和测量日期。必须区分“总宽增加 3 mm”和“两侧各增加 3 mm”，后者总宽增加 6 mm。薄膜、护角和外部加强件要有独立来源，避免在公差和包装模型里重复加厚。

例如有效净宽 2330 mm、每箱宽 580 mm，四列共 2320 mm；如果每箱总宽增加 3 mm，四列变为 2332 mm，原来的四列摆法失效。这里只能判断该排布失效，不能直接推断整柜数量一定减少四分之一，因为系统可能通过转向或换层重新安排。

输出至少包括标称方案数量、保守方案数量、原方案在保守尺寸下的失效位置、重新求解后的变化及临界参数。不得只按 CBM 比例缩减数量。没有实测分布时提供确定性的敏感性试算，不输出缺乏依据的装柜成功概率。

### 以实际包装外形作为装载对象

工具房、车棚的产品本体可能有凹槽和大片空腔，装入纸箱后仍应按纸箱外形占位。产品展示模型、运输包装模型和碰撞模型应分别声明关系。只有确认货物以裸件、可嵌套包装或经过验证的组合形式运输时，才允许利用真实凹槽；不能把展示模型的空腔直接当作装柜空隙。

对尖角金属件、透明板和涂层表面，补充禁止接触面、边缘防护和允许受力位置。允许嵌套还应给出嵌入深度、隔离材料和拆出条件，不能只凭两个实体没有相交就自动选择穿插装法。

### 托盘结构与设备接口

托脚、面板和底梁的数量应与参数严格一致，间距由明确公式计算。托脚根数或排数改变时，同一结构数据同时驱动三维模型、叉孔和碰撞代理；防止显示五个托脚而校验仍沿用旧孔位。

新增允许进叉方向、叉孔净宽净高、叉间距区间、货叉最大插入深度、叉尖余量和抽叉方向。托盘的静载、动载和货架载荷分别保存，不能互相替代。需要时录入载荷中心对应的设备能力，缺失时保留未知状态。

托盘表面仍可采用保守平台承托作为默认模式；细长或柔软包装应增加面板接触和悬跨规则。不能仅通过接触面积大就判定跨板缝放置安全。[E07 E08]

### 木箱结构与传力

木箱需要区分封板、外部加强条、立柱、底梁和允许受压区。额定顶载应绑定结构版本、朝向、支承条件和证据，不应仅绑定材质名称。

第一版木箱叠放只支持资料完整的明确承压区：上箱支承点落在下箱许可区域，已知负荷沿确认的立柱和底梁传递，逐层累计且未超过额定值。任一环节未知就标记未核验并保持默认底置。复杂板件应力和挠曲求解留待独立工程模块，不能由木纹或板厚外观推断。

### 动作顺序与搬运路径

将货物位置和作业动作分别建模。一次装托动作包括接近、进叉、抬升、通过门洞、落位、抽叉和设备退出。卸货时还要先拆除阻挡固定件，并确保后续货物的支承没有被提前移除。

现有路径支持有限的平移、抬升和水平九十度转向，最多分析每阶段前 60 件；它验证货物外包络的通道，不模拟叉车、人员或任意倾斜。[E09] 下一版应按设备模板检查完整扫掠体，显示受阻物、动作步骤、最小净距和未检查的项目。搜索预算耗尽时输出“未找到路线”，不能输出“绝对无法装入”。

### 装卸站次与完整套装

同一 SKU 可能分属不同客户、订单或目的地。现有站次按产品标识映射，建议增加订单行和批次身份，避免把同 SKU 的不同客户合成一种卸货站次。[E09]

完整套装约束增加明确层级：默认保持现有同托成套规则；必要时用户可以选择同柜成套并允许分托，但所有组成箱必须在同一交付柜且满足数量比例。该选择应进入备份、清单和版本记录，不可由算法自行放宽。

### 运输固定与作业预留

增加防滑垫、垫木、护角、绑带、气袋、挡杆、隔板等附件。每件附件有数量、尺寸、质量、用途和关联装载单元；有些占实物空间，有些还需要安装操作区。附件自重仅计入一次，并保留在清单中。

先支持手动标注固定方案与空间预留，再建设基于输入资料的固定核查。需要的摩擦、绑点、绑带能力、接触条件及运输工况应可追溯；数据不完整时只输出材料和布置记录。不得把柜壁默认当作任意点载荷的可靠支承，也不应让新增补货自动删除固定件。[S1 S5]

### 重量与受力口径

当前静态上压按接触面积分配累计重量，适合明确其假设下的规划；没有覆盖材料变形、运输动态或完整地板集中载荷。[E08] 下一步需要将货物自身重心、接触区域、箱顶累计负荷、地板区域负荷分别展示，突出未知参数。

纸箱输入重量按单箱毛重理解，已经包含纸箱及内部包装；外加托盘、木箱围护、垫木和固定材料另列，避免重复。柜内总装载重量用于核对载荷；计划整柜总质量再加柜体皮重。实际核重、称量时间和差额保留为独立记录。[S4]

### 现场变化与复核

到货少箱、包装破损、托盘缺货、临时换柜或门洞变小，都应形成变更记录。用户可锁定已打托和已装区域，仅重排剩余货物。被锁定区域因新数据失效时，系统应指出冲突并要求处理该对象，不可以静默移动。

备货顺序也应进入现场指导：先完成哪些托盘、需要预留多大暂存区、哪一托先靠近柜门。后期可估计倒托、换向、拆包和二次搬运次数，使方案比较更贴近仓库人工成本。

### 防潮标签与装载过程

金属工具房和车棚的长途运输还应记录防潮要求、干燥剂布置、不能贴靠的位置及包装完好性。先提供可配置的作业项和附件记录，缺少环境数据时不计算锈蚀概率或自动推荐干燥剂用量。主唛、侧唛和托盘标签应尽量朝向可查看区域；“标签可读”与“文字总在屏幕上层”分别处理。

最终布置可成立，也可能在施工过程中短暂失稳。高层码放、拆除垫木和先卸下层等动作，应检查每一步的支承关系。需要人员登高、临时支撑或特殊抬升的步骤要进入作业说明，而不是只在最终三维图中隐藏这些条件。

## 05 功能模块的具体需求

### R01 统一结果状态与交付视图

方案顶端分别显示数据一致性、几何、承托承重、路径、固定五类结果。每类采用通过、不通过、未核验、不适用四种状态，并写出基于哪份数据和哪种模型。总体显示已通过项目和未完成项目，不用单一“全部通过”概括资料缺失的方案。

点击问题能够定位箱体、托盘、接触面或动作，并跳转到对应参数。硬性几何冲突阻止采用现场方案；承重、设备和固定资料缺失允许保留测算稿，导出时持续带出未核验项目。是否允许签发现场作业版由项目规则明确配置，不能用普通查看权限替代。

客户报告和离线作业图复用真实投影与包装模型，包括孔洞、木箱围护和实际整托总高。目前 field-report.ts 的 planSvg 仍按矩形绘制，应优先补齐，防止屏幕与交付图含义不同。[E13]

### R02 托内编辑与层型设计

在单托独立查看中进入编辑模式，显示托盘局部坐标、箱数、套数、实际总高、箱级毛重、包装自重和剩余载荷。初版支持选中箱移动、水平旋转、按 SKU 增删箱、整层复制、交错层切换和移入移出指定托盘。

层型由相对底板高度与箱位集合定义，不能直接使用全柜 layer 序号作为每托的物理层。混合箱高时允许多个相交高度段，并显示该层的高度范围。复制后必须重新检查承托、承重、保护间隙、围板净空和完整套装。

每次操作作为一个事务写入统一撤销历史。拖动过程中显示预览；释放后通过统一校验才更新方案。删除或转移一箱同时修改该托清单与未分配池，不能凭空增加订单，也不能因删除一个组成箱留下被计为完整的残套。

锁定其他整托后，局部重排只能改变当前托和明确允许的未分配池。已采用方案生成新 revision；旧的二维码、现场进度和 PDF 不被无声替换。第一版不支持任意角度旋转和自动跨托拆套。

### R03 混合包装与尾数优化

保留 v0.28.0 的 1 至 8 种规格和库存限制，增加规格优先、少包装、低费用、少搬运等目标。先形成有限数量的打托候选，再按整柜收益、包装费用与尾货比较，显示搜索时间和当前最好结果。

尾数允许采用小托盘、低木箱或在规则允许时作为散箱，并明确需要拆托或重打的数量。包装库存和尾数选择要跨柜共享，不能在每柜中重复使用同一库存。缺少包装单价时不得输出最低总费用结论。

### R04 木箱叠放与支承核查

为木箱增加结构版本、额定顶载、许可支承区、底梁与立柱关联、允许朝向及来源记录。禁止以填一个总 kg 数值就绕过位置核查。通过明确支承条件的木箱才进入叠放候选；资料缺失继续底置。

结果同时展示上层施加的负荷、下层已用与剩余额度，以及承压区内外的接触。对超额负荷、错位支承、缺失证据给出不同原因。首次只支持参数化支承区，不实现材料有限元计算。

### R05 尺寸偏差与保守方案

增加批次级实测记录和增量规则，允许按 SKU、包装规格或整托设置。保守计算从原始输入派生新快照，保留标称方案，不能直接覆盖产品主数据。

原方案原位复核与保守尺寸重新求解分别输出。前者回答哪里变得放不下，后者回答调整后还能装多少。对长条箱给出每排、每层和门洞的最小余量；对临界方案显示需要核对的尺寸，不把数值小数精度当成测量准确度。

### R06 设备参与路径检查

设备模板至少包含本体、货叉、起升后总高、允许进叉方向、转弯空间和取放净距。装载单元绑定可用设备，重型或长件还可绑定经过确认的叉位和吊点。

从直线通道升级到分步动作检查后，保留现有快速模式。快速模式显示仅核查货物通道；完整模式报告设备和货物的扫掠。首版不自动评定任意设备的载荷能力，使用输入曲线与设备资料核对。

### R07 空隙利用与模型质量

空隙分为已证明空闲、未细分未知、保护预留、路径不可达和可尝试补货。几何空闲区域可以存在但不计入承诺的可补货容量。每次建议仍需经过碰撞、承托、承重、订单及路径复核。

补货对象扩展为完整套、完整托和明确允许的散箱。实体曲面显示近似误差和代理边界；导入模型出具单位、尺寸、封闭性、代理覆盖和简化信息。体积利用率继续区分实际实体体积与外包络并集占用，不把相互重叠的外接框简单相加。

补货与嵌套必须使用本次运输的包装模型。纸箱内产品的展示孔洞不进入空隙计算；裸件嵌套必须有允许深度、隔离与取出条件。

真实表面测量作为独立提升：测量端点绑定对象和几何特征，箱体编辑后跟随或显式失效。对外包络测量和实体表面测量分别标明来源，避免槽形件明明有空隙却测出零间距。[E02 E04 E10]

### R08 现场逐托交付

每个装载单元分配独立的 unitId，并绑定 planId、revision、订单行、包装版本和内容摘要。二维码指向经授权的只读单托页或可离线解析的有限数据；不能把浏览器本机文件路径当作手机可打开的链接。

单托页面显示箱数、套数、分层图、总高、毛重和未核验项目。扫码确认需要防重，允许记录缺箱、错 SKU、包装损伤、实测尺寸和照片。旧版本扫码时提示所属版本，不能把旧托号直接用于新布局。

初版可继续采用现有离线 HTML 与进度 JSON，增加逐托身份和异常记录。跨设备同步、团队权限和冲突合并放在后续服务端阶段，并保留本机计算的默认工作方式。

### R09 方案比较与业务目标

比较字段包括完整交付套数、柜数、运费、包装费、固定材料费、预计作业次数、尾货、未核验项目和路径检查范围。只把都有资料的费用相加，未知项明确留空。

支持数量优先、总成本优先和少搬运优先，保留备选方案与变化原因。给出改用小尾托、增加一柜、少装若干整套等选择的实际代价，不将启发式结果表述为全局最优。OR-Tools 的普通装箱示例只演示容量约束和柜数目标，不能直接代替三维几何、门洞与承托校验。[S6]

配重可由告警升级为明确的规划条件：用户按本次设备资料设置长向区间、左右差与局部地板载荷上限，再把这些条件纳入候选比较。阈值未确认时保留建议状态。整柜中心接近中间并不证明各区域载荷或车辆轴荷合格。

## 06 分阶段实施顺序

P0 是下一次交付必须处理的语义与一致性；P1 是下一阶段主要业务能力；P2 是进一步现场化；P3 是独立扩展。工作量为相对估计，S 为局部改动，M 为跨模块改动，L 为需要新数据模型与较多回归的工作，不构成工期承诺。

| 阶段 | 交付内容 | 优先级 | 主要依赖 | 工作量 |
| --- | --- | --- | --- | --- |
| A 可靠交付 | 统一校验状态 修正交付图 建立构建身份和 GPU 验收记录 | P0 | 当前快照与校验器 | M |
| B 整托编辑 | 托内移动增删 层复制 跨托转移 锁定局部重排 | P1 | A 事务和局部坐标 | L |
| C 保守测算 | 批次实测 附件增量 标称与保守双方案 | P1 | A 输入快照 | M 至 L |
| D 包装与承载 | 混合包装候选 尾数费用 木箱支承与顶载 | P1 | B C 结构额定资料 | L |
| E 现场动作 | 真实障碍 进叉抽叉 设备路径 固定件作业顺序 | P2 | C D 设备参数 | L |
| F 交付回填 | 逐托身份 二维码 异常回填 版本复核 | P2 | A B 稳定身份 | M 至 L |
| G 独立扩展 | 道路轴荷 任意倾斜 柔性形变 CAD 约束草图 | P3 | 单独定义模型和验证 | L |

建议 A 先落地；B 与 C 可以在共享输入契约稳定后分别推进。D 中“包装候选比较”可先实施，木箱叠放必须等待有效结构资料。E 先完成叉孔和门槛等确定几何，再接设备动作。F 的离线逐托身份可较早建设，团队扫码同步另行迭代。

首批实施文档见开发包的 001 至 004 计划，分别覆盖交付一致性、托内编辑、尺寸偏差和木箱叠放。每份含固定基线、修改边界、验证命令和停止条件。多规格包装已经存在，不将其重新拆成从零建设任务。

## 07 数据与校验契约

### 身份和版本

新增内容采用可迁移的版本字段，保留现有 productId、setCode、setNumber 与 palletIds。订单行、物理箱和装载单元分配稳定身份，布局重排只更新坐标和 revision；不能依靠数组序号判断同一托盘。

| 数据对象 | 需要增加的字段或信息 | 使用边界 |
| --- | --- | --- |
| 订单行 | orderLineId 客户 站次 批次 组成比例 | 相同 SKU 可有不同交付要求 |
| 实测记录 | nominal measured 增量口径 来源 日期 | 派生保守输入 不覆盖原始主数据 |
| 装载单元 | unitId 包装版本 托内局部坐标 内容摘要 | 全柜坐标由单元变换派生 |
| 结构额定资料 | 适用方向 顶载 支承区 条件 证据版本 | 未知与零承载分开表示 |
| 设备模板 | 本体 货叉 进叉面 起升边界 能力曲线 | 几何通过与能力核对分开 |
| 附件 | accessoryId 质量 几何 类型 安装依赖 | 防止重复计重和补货侵占 |
| 现场事件 | planId revision unitId 操作 内容 时间 | 防重 校验旧版本与冲突 |
| 校验记录 | 范围 状态 算法版本 证据 问题对象 | 所有导出读取同一记录 |

### 坐标与单位

计算保持 mm 与 kg 的现有内部单位。界面单位转换只改变显示。托内坐标以托盘底座的固定参考原点记录；柜内坐标通过单元位置与朝向变换得出。只打托的编组区位置继续标明为查看坐标，不冒充柜内坐标。[E06]

公差、保护距离、柜壁净距与数值误差分别建模。用于算法稳定的小容差不能被当作现场保护间隙。Z=0、底板顶面和木箱内部底面的含义要在所有编辑器一致。

### 每次编辑后的事务

操作先构造候选快照，再依次核对订单守恒、组成比例、包装净空、实体碰撞、承托、累计负荷、载重和路径影响。只有通过当前操作要求的校验才提交。失败保留旧快照并返回问题对象；通过后统一更新指标、清单、导出和现场版本。

承托面积按接触面的并集计算，不能把重叠区域重复计入。重量从上向下累计。强度输入缺失与数值为零分别处理：缺失表示未知，零表示禁止上压。方案各项通过只对已声明条件有效。

## 09 交付与现场试装条件

每阶段合并前执行仓库现有 npm run verify，并运行对应新回归；发布前执行 npm run build:pages。CI 通过结果关联到实际提交。浏览器验证采用同一输入文件，记录浏览器版本、设备、分辨率、WebGL 状态、部署 URL、构建提交和失败项。

真实 GPU 验收覆盖 Chrome、Edge、Firefox 和 Safari 的可用目标环境，并至少包括 Windows 的实际硬件。逐项验证旋转、正交切换、透明排序、拾取、手柄、剖切、全屏、尺寸开关和图片导出。软件渲染、SVG 降级和相机矩阵测试单独记录，不能合并成“真实 GPU 全部通过”。

建议先选三种代表订单试装：一种长条单箱、一种长短双箱套装、一种混合托盘加木箱。逐柜记录实测箱规、包装版本、设备、实际用时、返工次数、未装原因和货损情况。采用同一批样例同时校准和验收会低估误差，应分开保存两类样本。

阶段 A 的完成标准是状态和交付数据一致；B 的完成标准是托内操作可撤销且不破坏其他托；C 的完成标准是公差口径和双方案可追溯；D 的完成标准是木箱只在已确认支承条件下叠放；E 的完成标准是对声明覆盖的设备动作保留可复查路径；F 的完成标准是逐托记录可以与方案版本准确对应。

当前不优先建设高复杂度软体形变、任意角度穿插、自动材料强度推断和全自动运输固定认证。它们需要额外物理数据与验证。保持默认保守规则，并持续揭示限制，比增加未经校验的可视效果更符合实际出货需求。
