# 017A 整托搜索候选与逐订单行下界

版本：v0.55.0。所属 U09、U10、U23，整体仍为 PARTIAL。具体叉车操作继续 EXCLUDED。

## 问题与结果

固定案例 `pallet-loose` 保持 `business-2026-10-v1` 的原始输入。此前整托高密度原始搜索得到 31 箱，现场搜索得到 32 箱；主页面另有下界合并，而基准、整托 API 和多柜仍可能返回 31，调用入口不一致。

本轮把有限候选比较放在共同整托入口。保留原始高密度搜索；订单未全部装入时，最多增加一次完整现场候选。只有整体重新校验通过、总箱数严格增加且每个源订单行已装数量均不减少，才能采用该候选。保持柜型、门洞、原始订单、允许朝向、包装库存、支承、套装和指定散箱配额；不自动拆托或调换约束。原高密度候选更好或同量时继续保留。额外生成不可用或复核拒绝时保留原有效候选并给出提示。

该案例采用同一完整候选的货物、包装、余货和重量：A 12 箱、B 20 箱，合计 32 箱／340 kg；已装 1 托、4 个指定散箱。生成 2 托，其中 1 托未入柜；整单 A 余 18 箱。不能把原 31 箱方案的整托内容与新 32 箱坐标混合。

## 数量与来源

- 各源订单行 ID 分别计数；必装／优先行和套装成员不能被更多可选箱抵消。相同 SKU 名称不合并来源身份。
- 共同入口记录原高密度数量、补充候选数量、采用来源及比较状态；耗时包含两次尝试和复核。
- 基准 JSON 与界面公开 31 → 32 的来源，不把采用合法下界说成高密度原始算法自行搜索到 32。
- 主界面比较同样检查逐订单行不减量。若较大现场方案减少了某一行，保留原高密度组合，并显示组合待复核；数量较少不再误标为“数量一致”或“理论多 0 箱”。
- 搜索来源属于本次生成证据。恢复／编辑的坐标重新校验，不信任旧搜索标签；不能由恢复后的相同数量推断搜索独立收敛。

## 验证与边界

回归覆盖固定原始案例、共同 API、多柜费用和库存、整托自重与余货、无需补搜、原始候选更好、逐行不减量、套装完整性、几何／重量／包装／库存／散箱配额／朝向篡改、补充生成与独立复核失败，以及备份／CSV 和中英文来源提示。

这只是两种完整候选的有限比较，不是全局最优证明，也不能保证任意货物组合均达到现场数量。未实现自动经济尾数、拆托重打、跨柜联合重排、独立隐藏集和历史基准比较。实际 GPU、包装强度及现场试装仍须另行验收。正式测试和双站证据见 [v0.55.0 交付记录](../upgrade-v0.55.0.md)。
