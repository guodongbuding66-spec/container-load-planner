# 013J 尾数试算报告与候选逐行 CSV

2026-10-29；已发布 v0.69.0。接续 [013I](013i-three-group-tail-review.md) 的同订单、原包装库存、完整套装和逐行不减量约束，增加本批试算的留档功能，不增加新的求解范围。双站原生下载通过；GitHub CI 启动失败原因单独保留 PENDING。

完整批次结束后提供两类原生下载：

- JSON：格式 `cargo-fit-tail-trial-report`／版本 1；引擎、时间、原输入、基线方案 ID 与统计、搜索范围及各组上限、共享预算、全部候选的份数、已装数、逐行保留和复核问题、选中候选的逐行数量及五项复核。
- CSV：选中候选的全部源订单行，含稳定行 ID、同名 SKU 标识、原需求、原／候选已装与散箱预留、实际散箱、托内、未装，以及明确标为“候选整体”的五项复核状态。提供中英文标题、UTF-8 BOM、标准引号和换行、公式前缀保护。

报告一律标记 `preview-not-applied`，不会改变原输入或正式箱位。JSON 不是工作区备份，没有把报告作为已采用方案的导入入口；正式交付仍显式采用、重新计算并另存工作区。已发布版本可导出预览报告，`canApply=false` 如实保留。

## 完整性与失效

只导出当前已完成批次；运行中、停止、超时、线程错误、方案或权限变化及参数往返后的旧结果不可导出。序列化时检查各组、完整候选集合、重复或缺失组合、原订单、包装额定与选中候选的独立复核；再次校验选中候选属于本批次且各原已装行不减少。

完整运行但没有可采用增量时，JSON 保留全部已处理候选及原因，`selectedCandidate=null`；候选逐行 CSV 不可用。失败候选保留 `review-failed`，减量、无增量、可改善分别记录，不把“完成运行”等同于“每个候选均合法”。

采用模型校验和现有五项复核同源数据。几何通过仍可有承重资料、路径或运输固定未核验，报告不把缺资料升级为通过。具体叉车动作仍排除，账号／会员／支付未启用。
