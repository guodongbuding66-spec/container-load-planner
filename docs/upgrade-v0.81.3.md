# v0.81.3 输入箱数即自动打托，先微调再计算

2026-11-08（Asia/Shanghai）。

v0.81.2 仍将带结构资料的包装强制切回 current 模式，用户直接修改每托箱数时仍使用旧的 125 mm 净高；必须另点“设计新包装”才会生成新尺寸。上次只验收了额外按钮路径，没有覆盖用户直接输入箱数的常规操作。

本次修改：

- 输入每托箱数直接创建独立的新尺寸预览，保留订单和用户设置的箱数。单层结果页直接预览新尺寸，无须先点击重设计。
- 在预览旁微调托盘长、宽、底座高和托内净高，自动重新预览；采用前原方案不改变。
- 目标箱数装不下、数字无效、预览进行中或旧结果迟到时，不能采用；取消恢复已保存包装。
- 采用时同时提交尺寸与每托箱数，旧结构资料按 v0.81.2 规则保留，包装可用数量不增加。

回归使用与截图可见数据一致的重建订单：596 箱、1640 × 545 × 120 mm、42 kg、40HQ；旧包装 1800 × 1800 × 180 mm，每托 3 箱，未核验结构资料。原始工作区未取得，不声称隐藏参数或现场实物已验证。

保留每托 3 箱时，新预览为 1700 × 605 × 415 mm、3 层，两算法装柜为 21 托、63 箱；每托 20 箱时为 1700 × 1150 × 1255 mm、10 层、14 托、280 箱。单托箱数少会限制整柜数量，自动尺寸不擅自改变箱数或承重、堆叠许可。

新增交互状态回归覆盖直接输入、默认预览、保留 3 箱、采用前微调、尺寸装不下目标、空值、取消及过期 Worker 回包，并用真正的打托与装柜求解器校验结果。

验证：`npm run build:pages` 通过，167 个测试文件、2157 个测试、21 个渲染检查、类型检查、API bundle 检查及生产静态导出通过。ESLint 仅保留两个已有警告。
