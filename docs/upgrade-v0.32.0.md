# v0.32.0 木箱实体路径与独立叠放结构预览

日期：2026 年 10 月 16 日。基线：GitHub 4cc2d46ee8016c86582cef9adc4e5809dd7ee3e2（v0.31.0）。本轮范围见 [计划 005](field-upgrades/005-crate-structure-preview.md)。

## 本轮完成

上一版虽然四角支承区与底脚尺寸一致，但支承区域仍由一套独立矩形公式产生，没有逐段检查底脚、底板、立柱和箱盖是否连通。本轮在包装物理部件上标记角色和角部，显示与独立预检复用相同部件源。

每条路径从实际底脚开始，经过底板上同位置接触片、同轴立柱，终止于实际箱盖角部。检查唯一部件、有效正尺寸、底板及箱盖完整覆盖、同轴截面和相邻 Z 面连续；缺脚、重复部件、立柱偏移或断开、箱盖悬空均不能形成完整路径。整块底板及箱盖只贡献该角部的接触片，不将中部表面推定为立柱承压区。

跨箱接触使用上箱实际底脚底高和下箱箱盖角部顶高，并保持原有完整覆盖、唯一传力关联、包络包含、累计顶载、层数及逐路径保守上界检查。每条路径仍以本箱与所有上箱完整毛重之和核对，不按四角均分，也不将四条上界加成总重量。

## 独立结构预览

进入“方案工具 → 装载优化 → 木箱叠放预检”，点击“查看叠放结构与路径”。支持：

- 按现有箱号和四角选择路径，查看底脚、底板接触片、立柱、箱盖角部的实际坐标与三围。
- 拖动旋转、三维、长×高、宽×高和俯视；有 WebGL 时使用共享包装模型与正交相机，无 WebGL 时使用同源实体坐标投影。
- 只显示包装结构，不绘制箱内货物。模型没有改写当前箱位、订单、数量或毛重。
- 错位路径用红色定位，并保留下箱许可区参考。蓝色参考区不参与支承判定；只有实际完全覆盖才可能通过接触检查。
- 资料缺失显示灰色；几何连续单独说明“强度未核验”，不能把预览颜色理解为实际结构认证。
- 主方案过期、输入未就绪或偏移数字未完成时，结构预览与导出同步暂停。

本轮同时修正同源 CPU 投影在纯俯视时相机方向与 up 轴平行导致的无效坐标。纯俯视改用与视线垂直的 up 轴；普通视角保持既有行为。

## 版本与导出

人工核对键新增几何模型版本 four-corner-paths-v1。v0.31.0 的已核对标记会变为待重新核对，不静默继承较弱的几何依据；原输入资料与主方案坐标继续保留。

独立预检导出升级为 JSON v2，保留全部参与单元、四段物理路径、上下接触高度、实际匹配区域与仅用于显示的参考区域。导出重新计算预检结果，核对参与单元来自原方案中未改变的完整木箱；仅候选平移位置可以不同。无法把任意改重、换结构或改朝向后的单元冒充原方案。

该格式仍为 cargo-fit-crate-stack-preflight，不属于可恢复工作区，没有“采用”操作。资料、完整包装自重及原订单不会因预览增加；旧预检文件不会被当作新几何验收结果导入。

## 启用边界

**主求解器与整托独立校验仍将木箱底置，本轮没有启用自动叠箱。** 新模块验证的是参数化物理部件的几何连续性，不证明紧固件连接、材料强度、挠曲、运输动态、柜底集中载荷或设备搬运。没有实际额定来源时仍为未核验，没有提供或写入生产额定预设。

后续仍需将结构支承面与传力关联接入通用承托，在实际结构、额定资料及现场条件复核后单独启用自动叠放。封板中部、跨梁和多箱联合承托不由本轮推导。真实硬件 GPU 与多浏览器验收仍待完成；CPU 投影通过不能代替硬件 GPU 验收。
