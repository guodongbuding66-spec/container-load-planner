## v0.10 成套、实装校准与现场执行差异化

参考产品公开文档要求同一套装填写相同套装名称，并以套内数量表达 1:4、1:1 等比例。本项目在此基础上额外打通：

1. 不限制两箱或五箱，一键创建 2–5 箱后仍可继续增加箱型。
2. 输入阶段立即计算箱规种数、每套总箱数、完整套数与比例外零散箱。
3. 数量不对齐时提供“安全向下对齐”，明确不擅自增加订单数量。
4. 求解时任一组成箱失败即整套回滚，校验器独立复算各 SKU 是否得到相同完整套数。
5. 体积/载重倒推自动按套内比例取整，并再次运行真实几何求解。
6. 每个摆放箱写入套装编码、套号和套内序号，码垛提示、JSON、坐标 CSV 使用同一追踪数据。
7. 现场策略优先将不同箱规分成连续作业区，也可使用整层模块；单箱补位只允许第二种同高度平面方向，不侧翻塞缝。
8. 摆放结果会做支撑依赖拓扑排序，逐箱指导顺序不会先出现尚无承托基础的上层箱。
9. 已知实装包装以历史套数作为现场目标上限；未知包装同时显示稳健估算及平均/P90/最大回测误差，不作虚假精度承诺。

## 下一阶段算法模块

以下功能不能只做一个开关，必须进入求解、校验、导出和三维表现，因此按独立模块推进。

### P1：现场装卸规则

1. 每 SKU 摆放间隙与涨箱补偿；用“占位包络”计算，但三维仍显示真实外箱。
2. 目的地/仓库空间顺序、允许交叉深度，以及按箱门方向生成卸货序列。
3. 订单群组不可拆分、只允许同组混装（任意多箱成套比例已在 v0.6 完成）。
4. 单箱顶部承重上限与承重等级，校验重量沿支撑链向下传递。

### P2：托盘和人工调整

1. 托盘模板、出边、限高、混托/单品托和尾数处理。
2. “先打托、再装柜”的两阶段优化，以及托盘与散货混装。
3. 三维拖拽、吸附、旋转、锁定、撤销/重做；每次编辑后实时碰撞、重心和载重校验。
4. 固定局部方案后重新计算剩余空间。

### P3：多柜与业务协同

1. 多柜型自动选型、柜数最少、运费最小和指定柜型顺序。
2. 方案版本、只读分享、二维码现场查看和货物定位。
3. Excel/PDF 报表模板、箱唛和分步骤图片指导书。
4. ERP/WMS API、团队角色、审计日志与长期产品/柜型数据库。

## 验收原则

- 任何约束都必须同时影响求解器和独立校验器。
- 三视图、三维、进度、坐标和导出必须使用同一份摆放结果。
- 自动方案与人工调整都不得产生越界、重叠、悬空、超载或违规方向。
- 大订单优先保证浏览器稳定；三维采用实例化渲染，并提供 GPU 不可用降级。
- Cloudflare Pages 部署不依赖持续运行的传统服务器；需要账号、共享或 ERP 集成时再引入 Workers、D1/R2 等服务。
