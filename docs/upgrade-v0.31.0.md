# v0.31.0 木箱额定资料与独立叠放预检

日期：2026 年 10 月 16 日。基线：GitHub 00e94a6eb82a3396927a226ddbe9d414df454cc6（v0.30.0）。

## 本轮交付与启用边界

新增实际结构的额定资料、四角承压脚模型、许可支承区、独立叠放预检及资料状态显示。**自动装柜仍将所有木箱底置；本轮没有启用自动叠箱。** 独立预检没有“采用”操作，不修改主方案的箱位、数量、套装、重量或现场进度。

计划 004 的停止条件是：“若需要改引擎通用碰撞或放宽套装规则，停止并另立计划。” 另有要求：真实结构超出离散支承区、传力依赖材料挠曲，或没有明确额定资料时，停止启用生产叠放。

实际核对发现：floor-pallets.ts 的 palletAnchors 只提供底座承托；当前通用承托尚未把立柱与箱盖角部作为独立真实承托面。palletize.ts 的 topCapacity 对木箱仍返回 0；prebuilt-pallets.ts 仍拒绝抬离柜底的木箱。本轮保留这些限制，不用虚构整块平顶、关闭校验或把资料齐全标成主方案结构通过。

## 录入与版本绑定

在打托配置的包装编辑器中选择木箱，展开“木箱额定资料与支承区”。支持三种资料状态：

- 资料缺失／未核验：默认状态，不附带任何生产额定数值。
- 明确禁止叠放：独立于缺少资料；额定顶载为 0 也禁止上压。
- 录入额定资料：结构版本、来源／文件编号、适用条件、可选有效期、允许水平朝向、额定顶载、总层数，以及四条传力路径各自的额定值。

首版结构限定为 **四角承压脚＋框架或条板围护＋箱盖**。每个接触区对应同位置底脚、立柱与箱盖角部；其他底座、封板中部受力、跨梁、多箱联合承托不能用该模型核验。新底座在三维和降级预览中实际生成四只底脚，尺寸与许可区一致。

所有必要字段、支持结构与正路径额定值齐全后，用户才可标记“已人工核对本结构版本、额定来源与实际适用条件”。资料与结构精确绑定，不作为文件真实性或第三方认证签名。尺寸、底座、围护、材质、自重、限高或额定资料发生变化，原核对标记失效；颜色、透明度与显示名称不影响结构绑定。到期资料变为未核验。

## 独立预检

完成打托／装柜后，在“方案工具 → 装载优化 → 木箱叠放预检（独立试算）”选择现有完整木箱。从下向上添加，最多 20 只，不得重复使用同一只箱，不复制订单或重量；保留原整箱朝向。可以逐层设置相对下箱的 X、Y 偏移，起点在独立预检坐标系，不是柜内摆放坐标。

检查包括：

- 每只箱的结构、完整自重、外尺寸、箱盖总高、额定资料与朝向一致。
- 每只上箱底脚由下箱一个许可区完整覆盖；四角关联唯一，不能只凭封板中部接触通过。上下箱之间不能穿透、悬空或外伸。
- 箱内货物不超过包装承重；各箱累计上压不超过额定顶载，所有支承箱都满足自身额定总层数。
- 多层累计包含每只上箱的货物和完整包装自重，仅计一次。

对于第 i 层，设本箱完整毛重为 G_i，所有上层完整毛重总和为 A_i。额定顶载检查 A_i；**每一条路径**均用 G_i + A_i 作为保守载荷上界。四条上界不相加当作货物重量，也不假设四角平均分担。该模型可能拒绝实际结构可以承受的排列，但不会通过除以四来制造容量。

结果区分“按录入额定值预检通过（未采用）”“不通过”“未核验”“禁止叠放”，按箱号与角部定位原因。只有一只箱时不显示叠放通过。未完成数字、过期主方案或输入未就绪时暂停预检和导出；重置同时清空未完成的数字草稿。

预检不是实际材料试验，不覆盖车辆地板、叉车、转运、运输动态或绑扎。真实结构不能用首版四角模型表达时，保留未核验。

## 可视化、快照与报告

- “承重”工具新增“木箱额定资料状态”颜色。颜色表示已核对／未核验／禁止叠放，不表示木箱承托或材料强度已通过；原托盘负荷和逐箱上压保持原语义。
- 工作区、包装模板、归档与独立尺寸对比报告保留相同资料。旧备份无此字段仍按原单层规则处理。
- 恢复单规格历史坐标时，额定资料必须与工作区输入一致；多规格沿用完整规格一致性检查。资料来源被替换不能静默继承旧标签。
- 坐标 CSV 在存在资料时附加木箱额定资料 JSON、资料状态与核验范围；货物行和木箱行均关联相同资料，不增加重量记录。
- 客户报告、离线指导书与 PDF 增加按规格分组的额定来源、版本和条件摘要；始终注明主方案底置。PDF 长字段截断为摘要，完整内容保留在工作区／坐标 JSON 中。
- 预检导出采用独立格式 cargo-fit-crate-stack-preflight，保存来源方案、引擎版本、完整参与单元、候选位置与计算依据；不能作为装柜工作区恢复或现场方案采用。

## 验证

专项覆盖：新模型恰好四角脚、水平旋转后的区域对应、旧数据默认未核验、禁止状态、资料缺失／过期／失效、错位和缺区、超顶载、单路径保守上界、多层累计与层数、额定朝向、负载和结构记录不一致、源方案不变、备份／CSV／PDF、源资料替换拒绝及中英 UI。

测试里的正额定资料均明确标为 SYNTHETIC-TEST-ONLY，不写入生产预设或默认模板。尚未提供实际木箱额定来源，实物结构验收与真实 GPU 验收仍待完成。

完整检查：767 项 Vitest（64 个文件）、21 项 HTML 结构检查、TypeScript、零 lint 错误（3 项既有警告）与 Next 静态生产构建通过。PDF 长字段和版本绑定边界另做专项复核。

## 下一阶段

为真实立柱、箱盖角部和底脚建立统一承托表示，在候选进入方案之前完成结构承托和载荷检查；在明确额定资料与实际结构验收完成后，再单独启用自动叠箱。封板、长底梁、挠曲与多箱支承属于后续模型，不能由本轮推导。

设计原则参考：IMO/ILO/UNECE CTU Code 的堆码规划要求包装强度适合叠放设计。该原则不提供本软件的木箱额定值，也不构成对本模块的认证：[UNECE 堆码规划](https://wiki.unece.org/spaces/TransportSustainableCTUCode/pages/23102042/1%2BPlanning%2Bof%2Bpacking)、[IMO CTU Code](https://www.imo.org/en/ourwork/safety/pages/ctu-code.aspx)。
