# v0.47.0 跨柜共享库存与运费、包装费比较

日期：2026-10-20。基线 main `10c16a2cf72df874ad598ca8be4da6e82306e095`，源树 `c910067dd1cce189660ee8a89d1f4b411f32651a`。

先打托后装柜接入整单多柜工具。各规格包装可用数、全单包装上限及按 SKU 指定的散箱数量只共享一次；候选试算不扣库存，仅对实际入柜实物扣减。每柜仍完整求解，再独立复核全单订单、套装、库存、重量和费用。

## 范围与边界

- 完整装完订单的候选优先；未完成候选保留必装及高优先级完整货量，再按柜数或已报价费用比较。尾柜优化只重建最后一柜或两柜，已采用前缀保持不动。有限启发式不证明全局最优。
- 同币种输入运费及各包装单价；包装明确勾选已报价后可为 0。沿用旧版约定，运费 0 为未报价。未知费用不称免费，费用优先需完整报价。比较费用范围仅运费与包装，固定材料、人工、重打、税费及换汇未计。
- 实际入柜包装与试算未入柜单元分开；后者可对剩余货物重新打托，不代表仓库已制作的实物。不拆已入柜整托，不承诺返工免费。底部铺托盘仅补费用报价，原有逐柜铺设规则不变，不标为共享预打托库存。
- 独立 JSON 保存来源订单、包装规则、柜型可用数、目标、报价及全柜实物；恢复重新校验，来源与当前工作区不一致时拒绝混用。CSV 增加柜号、库存、散箱和费用汇总，各柜局部实物 ID 由柜号区分。
- API 兼容：旧 `FleetResult.totalCost` 保留运费小计语义；运费加包装的可比合计为 `costs.total`，未完整报价时为 null。工作区旧备份格式不改；新增多柜备份格式为 `cargo-fit-fleet-v1`。
- 预打托各柜保留原订单站次和静态通道输入。路径复核超过 240 个装载单元时明确未核验，不把省略当通过。具体叉车作业仍 EXCLUDED；真实 GPU 与现场试装仍 PENDING。
