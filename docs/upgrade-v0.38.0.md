# v0.38.0 连贯搬运与承托切换

日期：2026 年 10 月 18 日。基线 v0.37.0，GitHub `54eb0989636d3c6011c462e26631931e891d31c5`。本轮为 [010B](field-upgrades/010b-handling-sequences.md) 首阶段软件，完整设备搬运 U05 保持 PARTIAL。

## 行为

整托清单增加“连贯搬运预检”。使用有来源和版本的设备、现场及当前托盘／双叉资料，手工填写门外整托实际 X、搬运起升、接近和退出额外距离，生成七步：接近、进叉接联、起升、直线搬运过门、落位支承、抽叉解联、退出。没有设备尺寸默认实测值；明确零行程也必须填写。可编辑各终点，下一步起点联动；生成参数修改后须重新生成，当前任务版本单独显示。

限定底置完整托盘、朝后门正 X 进叉和齐平地面。LWH 的 x-max 与 WLH 的 y-max 使用同一世界坐标轴。步骤 X／Y 相对最终箱位，起升相对柜底，门外 X 与扫掠输出使用实际柜内原点。门外初始／最终整托须完全落在已建模地面内；不推定跨门槛或坡道支承。

每步检查连续扫掠和衔接状态：足量进叉后才能起升；载货保持接联，起升后才能平移；到指定目标并降至地面后才允许完全抽叉。断链、跳步、横移、悬空解联或中途几何失败，后续显示未执行。脱离时目标托按当前实际位置检查，解决从门外装入及在门外抽叉时把目标误留在原箱位的问题。其他货物、邻托及全部前／后装附件始终是障碍。

## 保存与交付

当前两套算法分别保存原始逐托任务，保留另一算法方案。工作区备份包含两套坐标及各自任务；恢复严格解析原始参数，删除导入的伪造结果，现场或箱位资料变化后必须重绑并重新检查。资料指纹只用于标记变化，不是安全认证，也不绕过重新计算。

独立 JSON、坐标 CSV、客户／离线报告和 PDF 都基于同一原始任务重算。PDF 单独逐托列出七步、状态及失败 ID，完整来源和扫掠在工作区与独立 JSON。任务不改箱位、订单、库存、数量、重量及五项复核；交付指纹包含任务版本。保存到当前页面方案后，需下载工作区备份保留；不承诺刷新自动恢复未保存箱位。

同时修复切换装载工作流前有效数字草稿未提交的问题，避免输入尺寸后切换工作流又恢复旧值。

## 两站实际验收

- 两个正式域名均显示引擎 0.38.0。默认直接装柜订单两套算法均为 116 箱、3,842 kg，布局校验通过；Vercel 切换默认订单到先打托后装柜，两套算法均为 76 箱，新逐托入口正常。未填写动作尺寸时阻止生成，没有默认通过。
- Cloudflare 使用明确标记 QA 的一托小例：SHED 400 × 400 × 200 mm、10 kg、1 箱；另外两个 10,000 mm 长件仍在未装订单中。两算法各 1 箱、1 托、35 kg，订单总重仍为 69 kg。底座、双叉、设备和现场均为软件测试资料，不是实物额定证据。
- 缺门框／门外资料时，在第四步转运处未核验，第五至七步未执行。补齐齐平地面和矩形边界、重新绑定后，卸出七步通过。把第五步落位高度改为 50 mm，明确报告未获地面支承、禁止解联，第六／七步未执行；恢复 0 后通过。
- 车宽改为 2,600 mm，旧结论立即失效且禁止导出；重新绑定也不能覆盖干涉，第一个接近步骤定位车体越过侧壁。恢复 600 mm 后通过。任务重开保留全部输入，但不会自动复用检查结论。
- 实际卸出 JSON 的接联状态为 false / true / true / true / true / false / false；地面支承状态为 true / true / false / false / true / true / true。四个脱离阶段各有 4 个部件扫掠，三段载货动作各有 5 个；车体与门架不随起升悬浮。见[实际 JSON](field-upgrades/evidence/v0.38.0-handling-sequence.json)和[页面截图](field-upgrades/evidence/v0.38.0-handling-sequence.jpg)。
- 现场算法保存卸出任务，高密度算法保存从门外装入任务，两者七步均通过。实际下载的[工作区备份](field-upgrades/evidence/v0.38.0-workspace.json)保留两套箱位、托盘及各自任务，没有缓存的通过标志。使用当前恢复函数读取该下载文件并重新预检，两套仍各 1 箱、35 kg，十四个步骤全部通过。
- 实际坐标 CSV 的任务及检查列与独立 JSON 一致，所有行列数一致。网站实际生成 8 页 A4 PDF，第 6 页完整列出七步、来源版本、未执行／未核验范围及页脚，中文和坐标无溢出，见[PDF 任务页渲染](field-upgrades/evidence/v0.38.0-sequence-pdf-page.png)。HTML 的同源结果与来源转义由专项单元测试覆盖。
- 英文已保存任务重新预检，七步及总结果通过，整个预检对话框未见中文残留。有效长度草稿 400 → 410 mm 后切换工作流仍保留 410 mm，随后恢复测试值。
