# 外贸装柜智算

面向外贸报价与出货计划的浏览器端装柜测算工具。当前引擎 v0.21.0 支持单品最大装柜量、多 SKU 拼柜、任意多箱套装原子装载、报价经验/三维物理双轨输出、现场易执行/高密度参考两套独立求解器、先完成先展示的后台并行计算与热线程复用、真实装柜数据校准、目标利用率计划与装载上限分流、柜内到箱门的承托安全执行顺序、真正的透视/正交投影、三视图控制三维相机、逐箱码垛导航、现场指导书、重心提示、独立合法性校验和坐标导出。

## 当前功能

- 配置页、装载空间库、3D 装载视图与全屏查看共用简化实物模型：集装箱侧壁筋、柜门和锁杆，货车驾驶室、底盘与车轮，冷藏机组及开放式柜体；支持实物模型／线框切换，默认 65% 透明度，可调整至 0–100%。外形为通用示意，模型结构不占用输入的可装载空间
- 三维尺寸采用工程三边标注：蓝色尺寸线、带轴名和单位的青色文字，固定像素字号、边缘避让和标签排布，始终面向屏幕且不被模型遮挡；支持 mm / cm / m 与 14 / 18 / 22 / 26 px。尺寸开关统一控制柜体、选中箱体、托盘、预览与全屏，关闭后保留选中轮廓但清除全部尺寸线与文字；箱标开关控制所有 SKU 浮动标签和箱面标签，选中不再重复生成 SKU 标签。正交轴向视图隐藏投影重合的轴，尺寸层保留在 3D 图片导出中。无 WebGL 时，配置页使用同一几何数据的可旋转 SVG 模型预览，装载结果使用支持选择与标注的完整真实坐标俯视图，取消前 500 箱的绘制截断。

- 20GP、40GP、40HQ 柜型预设；可修改参数、命名并在本机保存多个自定义柜型
- 自定义目标体积利用率与载重利用率，分别倒推容量；单品多箱时优先显示完整套数，并附对应箱数明细
- 一键把倒推数量应用到订单，再执行真实门洞、几何空间、堆叠与载重验证
- 默认“现场易执行”策略：按柜型采用 20GP 80.5%、40GP 84.5%、40HQ 88% 的可调经验基线；优先生成 SKU 连续分区、整层模块或主网格+侧条补位，每个 SKU 最多两种同高度平面方向且不侧翻，非地面箱体至少 99.5% 受托
- “现场易执行”和“高密度参考”不共享同一个候选选择器：每次计算会在两个可取消 Worker 中并行运行现场分区/整层算法，以及三维分段动态规划+多起点自由空间搜索，并缓存两套完整坐标；之后切换按钮会同步切换预测套数、三视图、3D、指标、打印和导出，不再只改变按钮高亮
- 三步流程：先完成货物录入，再确认柜型、可选底层托盘和装载规则，点击“开始计算”后统一生成双算法快照。前两步编辑仅保存草稿，不运行求解器；长、宽、高仍支持跨字段、跨行一次提交。方案阶段可自行开启 280 ms 防抖自动更新。计算期间隐藏已过期坐标，数量、套/箱口径、进度、三视图、3D、指标和导出只读取当前选中方案，避免局部刷新造成自相矛盾
- “统一建议量”取体积/载重算术目标与当前算法已校验坐标上限的较小值，并按完整套数向下取整；例如算术上限 529 套而坐标只能装 528 套时，页面和操作入口统一显示 528 套
- 理论求解会反向指导现场求解：单品/套装只自动吸收保持原包装高度、最多两种水平朝向、99.5% 以上承托且形成连续作业区的安全子方案；多 SKU 复用理论搜索发现的多起点排序线索，但会在现场约束下重新摆放和校验，不直接复制理论坐标；复杂增益只作为试装参考
- 相同包装命中历史实装时，柜型默认现场目标继续以真实数量为基准；只有用户主动把现场目标提高 1 个百分点以上，才解除旧记录硬封顶，并用通过现场约束的理论安全子方案生成挑战性试装坐标
- 单品模式中“现场易执行”严格服从体积/载重目标，“高密度参考”显示不保留软目标余量的启发式独立结果；双箱回归场景会分别切换为现场 476 套/952 箱与高密度 528 套/1,056 箱。高密度结果不是全局最优证明
- 多箱套装助手可一键创建 2/3/4/5 箱结构，并可继续追加第 6 箱及更多箱型；同一套支持 1:4、1:2:2 等任意整数比例
- 相同套装编码的多个 SKU 可定义每套箱数；任一组成箱放不下即回滚整套，结果只输出完整套数
- 输入端实时显示箱规种数、每套总箱数、可组成套数、比例外零散箱，并可安全向下对齐而不擅自增加订单数量
- 倒推箱数会自动对齐套装比例，结果区单独展示需求套数、已装套数、未装套数和组成箱明细
- 每个已装箱写入套装编码、套号和套内序号；单品多箱时码垛进度、三视图与当前步骤均以完整“套”为主单位、箱数为明细，JSON 与坐标 CSV 仍保留逐箱追踪
- 单品最大装柜：遍历允许方向，联合体积、门洞和载重约束计算规则排布
- 多 SKU 拼柜：按数量与优先级执行极点启发式装箱
- 每个 SKU 可设置固定方向、仅平面旋转或任意旋转
- 每个 SKU 可设置是否允许上方承托，以及最大堆叠层级
- 自动计算长向、横向和高度重心，并提示是否位于建议区间
- Web Worker 本机计算，订单和产品数据默认不上传
- WebGL 交互式三维视图；WebGL 不可用时自动切换为真实坐标俯视图
- 俯视、侧视、箱门三视图用于校核；点击任意视图，三维相机会切换到真正的正交投影、对齐精确轴向并重新适配完整柜体
- 3D 可独立切换透视投影/正交投影，并提供等轴测、俯视、侧视、箱门快捷方向；手动拖动后自动进入自由视角
- 逐箱上一步/下一步、1×/2×/4× 播放、拖动进度与当前箱坐标提示
- 多 SKU 可区分“必装货物”和普通塞货；支持必须底置，并将两项规则纳入独立校验
- SKU 显隐、体积/载重利用率、未装数量、告警和独立校验报告
- 产品 CSV 导入、坐标 CSV 导出、完整方案 JSON 导出，以及适合打印或另存 PDF 的现场装柜指导书
- CBM 由长×宽×高自动计算，主值保留两位、审计值保留四位；不再要求人工重复录入 CBM，几何求解始终使用未四舍五入的真实尺寸
- 内置用户测试尺寸、“1 套 2 箱”“1 套 5 箱”、四组用户实装记录和真实 SLM-A64M 数据；Loading Qty 统一按套数处理
- 长、宽、高采用一次编辑事务：可跨字段、跨行连续录入，离开尺寸输入区后统一提交；第二步确认后计算。换单位前先提交当前尺寸，避免丢失未提交数值。
- 本机草稿自动保存

## 约束模型

当前几何最小装载单元是“运输外箱”；配置套装后，业务最小装载单元升级为由任意数量外箱组成的原子套装。算法考虑：

- 柜内有效边界与安全间隙
- 箱门宽高
- 外箱旋转／禁倒置规则
- 必装优先与必须底置
- 套装编码、任意 SKU 数、任意整数比例、整套回滚、套号追踪和完整套数独立校验
- 是否可承托与最大堆叠层级
- 集装箱最大载重
- 箱体碰撞
- 极限模式允许三维方向搜索，非地面箱体至少 68% 底面受托；现场易执行模式至少 99.5% 受托、禁止侧翻，并限制为最多两种同高度的水平 90° 方向

## 真实数据校准与双轨输出

当前保存 13 个包装记录、39 个柜型 Loading Qty 数据点；其中 12 条物理可行记录组成 36 点留一回测。对尺寸完全匹配的历史包装，报价经验轨直接回放已核实套数；对未知包装，系统从可行记录动态计算各柜型稳健 CBM 中位基线（当前约 26.30 / 56.30 / 66.08 CBM），回测平均误差约 1.7%、90% 数据点不超过约 4.6%、最大约 6.6%。这些统计不会被表述成对所有未知包装的虚假 3% 保证。

用户最新提供的四组实装记录已进入算法级回归：

| 包装 | 20GP | 40GP | 40HQ | 现场三维最大误差 |
|---|---:|---:|---:|---:|
| 180×15×10 + 127×55×29 cm，1 套 2 箱 | 110 套 | 230 套 | 275 套 | 0% |
| 189×75×14 + 168×17×16 cm，1 套 2 箱 | 110 套 | 230 套 | 270 套 | 0% |
| 167×73×13 cm，1 套 1 箱 | 175 套 | 360 套 | 425 套 | 约 1.18% |
| 164×54.5×12 cm，1 套 1 箱 | 235 套 | 505 套 | 600 套 | 0% |

旧双箱记录的净重/毛重标签与箱明细相反，系统按 15 + 31 = 46 kg/套作为保守毛重。新双箱记录顶部虽写“1set / 1 ctn”，但两行箱规可完整加总到 76 kg 净重、85.8 kg 毛重和 0.25 CBM，系统因此按 1 套 2 箱录入；两种源数据矛盾都会显示质量提示。

SLM-A64M 仍是刻意保留的异常样本：Loading Qty 已确认是 396 套，但按两箱实际尺寸需要约 126.7 CBM，超过 40HQ 物理边界。系统的报价轨显示 396 套，三维轨只生成零重叠、可校验的物理方案，并明确显示差距；绝不会把 396 套伪装成可执行坐标。

当前版本已支持单箱累计上压承重和柜内底层托盘；已提供预先打托整组装柜、卸货站次与直线路径检查；尚未模拟绑扎、机械抬升转向和道路轴荷；重心目前作为测算与告警指标，不作为强制淘汰条件。正式出货前仍需复核实际柜型与包装数据。

多箱套装使用说明见 [`docs/multi-carton-sets.md`](docs/multi-carton-sets.md)，参考产品功能覆盖、差距与后续算法路线见 [`docs/feature-benchmark.md`](docs/feature-benchmark.md)。

- React 19 + TypeScript
- Vinext / Vite
- Three.js + React Three Fiber
- 纯 TypeScript 装箱引擎与 Web Worker

## GitHub → Cloudflare Pages 自动部署

仓库已同时保留两条构建路径：

- `npm run build`：生成当前完整 Worker/Sites 构建产物。
- `npm run build:pages`：生成纯静态 Cloudflare Pages 产物到 `out`，装柜计算、Web Worker、三视图和 3D 都继续在浏览器本机运行。

Cloudflare Pages 连接 GitHub 时使用：

- Production branch：`main`
- Build command：`npm run build:pages`
- Build output directory：`out`
- Root directory：`/`
- Node.js：由 `.node-version` 固定为 `22.16.0`

`wrangler.jsonc` 已将 Pages 项目名和输出目录纳入版本控制。Cloudflare Pages 会注入 `CF_PAGES=1`，因此 `next.config.ts` 只在 Pages 构建时启用静态导出，不影响现有完整构建。Pages 构建固定使用 Webpack，确保装柜计算 Worker 被编译为可直接在浏览器运行的独立脚本。

## v0.18 柜内底层托盘与三维细节

- 工具栏“柜内底层托盘”使用同一个托盘库，包括自定义托盘；配置长、宽、底座高、自重、承重、数量、间隙和水平铺设方向。数量 0 自动铺设；可允许余下货物直接放在柜底。
- 托盘以固定柜底支撑进入求解器，货物 Z 从托盘顶面起算，纸箱层数不把托盘计为一层。托盘占用包络和自重计入空间占用、载重、重心及倒推目标，货物箱数和 SKU 清单只计货物。
- CSV 增加记录类型、托盘关联，并单独列出托盘行；JSON / 工作区归档、三视图、PDF 和离线指导书保留相同物理记录。恢复会验证托盘配置与记录一致并重算承托、承重及所有指标。人工调整和继续优化保留托盘支撑。
- 木托盘显示顶板、横板、9 个支撑块及底部跑板和叉孔；低矮航空托盘显示平板。已有“托盘货物”的底座仍包含在外包装总高内，不重复加高。
- 三维箱标按每个箱面的物理比例生成纹理，全 SKU 自动换行；标签可开关。毫米空间刻度随镜头保持可读，隐藏与视线重合的轴。点击箱子显示尺寸线、XYZ 和托盘关联，并可聚焦放大；取消固定雾化遮挡，窄屏远景不会隐藏货物。
- 坐标延续原有有效柜内空间原点，X/Y 的安全边界已从净空扣除；Z=0 是柜底。板块造型为通用外形示意，承托仍按托盘平台外包络核算，不模拟板缝处的纸箱挠曲。承重上限和自重应按实际托盘填写。

## v0.19 三步装柜流程与尺寸模型

- 第一步提供箱规、毛重、数量、单位和套装录入；详细规则可展开，货物类型与独立方向仍可在“货物详情”中设置。示例与真实记录收纳到单独菜单。
- 第二步直接显示集装箱／货车尺寸模型和可选托盘配置。无托盘不扣减空间；启用后展示按实际 L/W/H 生成的可旋转板块模型、铺设俯视图、自重、占用容积、货物可用容积与托盘上方净高。
- 托盘货物限高从平台顶面计算，0 按柜高及门洞自动限制；整托总高不能超过门洞净高。规则进入两个求解器、人工修改、继续优化、独立校验和归档恢复。仅与托盘相连的货物受该限高约束，允许的散箱柜底区域仍使用柜体空间。
- 第三步统一显示货物和真实托盘、空间扣除等式、剩余载重、独立托盘清单及抬高后的货物 XYZ；CSV、JSON、PDF 和离线指导使用相同数据。托盘外包络仅扣除一次，叉孔不作为可用货物空间。
- 上一步／下一步保存已完成的托盘及规则输入。未填写完、超载、无可行托盘铺设会阻止开始计算。返回配置暂停正在运行的计算，过期结果不能导出。
- 保留 SKU 独立承托比例：仅修改布局、搜索或货物顺序不会覆盖每个产品的承托设置。开启或修改承托规则时才应用同类型比例。
- 托盘形状为通用板块结构，并非特定厂家板厚的工程图；容积采用外包络，承托按平台包络、额定承重按输入值。当前不进行整托叉车路径或绑扎仿真。
